## 3. 내 컴퓨터에서 서버 켜기 (개발용)

### 3-1. 준비 (처음 한 번)

1. Python **3.11**을 설치합니다. (3.14는 일부 패키지가 동작하지 않아 쓰지 않습니다.)
2. 저장소 맨 바깥 폴더에서 가상환경(venv)을 만들고 켭니다. *가상환경 = 이 프로젝트 전용 도구 상자*입니다.

```
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -r backend/requirements.txt
```

   활성화되면 줄 맨 앞에 `(.venv)`가 보입니다. (맥/리눅스는 `source .venv/bin/activate`)

3. 맨 바깥 폴더에 `.env` 파일을 만들고 `.env.example`을 참고해 값을 채웁니다 (§5).

### 3-2. 서버 켜기

```
cd backend
uvicorn main:app --port 8000 --reload
```

- 브라우저에서 `http://127.0.0.1:8000/health` → `{"status":"ok", ...}`가 보이면 성공입니다.
- 자동 설명서(Swagger): `http://127.0.0.1:8000/docs`
- **주소는 `localhost`가 아니라 `127.0.0.1`을 씁니다.** Windows에서 `localhost`는 요청마다 약 2초가 더 걸립니다.

### 3-3. 앱 켜기

```
cd frontend
npm install        (처음, 그리고 git pull 로 package.json 이 바뀐 뒤에는 매번)
npm run web
```

- 앱이 서버를 찾는 주소는 `frontend/.env`의 `EXPO_PUBLIC_API_URL`입니다.
  - 내 컴퓨터 서버를 쓸 때: `http://127.0.0.1:8000`
  - 운영 서버를 쓸 때: `https://pet-walk-t01-z095.onrender.com`
- `.env`를 고친 뒤에는 **앱을 껐다 다시 켜야** 반영됩니다.

### 3-4. 테스트

```
pytest                  (저장소 맨 바깥 폴더에서)
```

2026-10-15 기준 서버 테스트 **443개 전체 통과**. 이 테스트는 실제 Supabase를 건드리지 않고 메모리 안에서만 동작하도록 격리되어 있습니다.

## 4. 운영 서버(Render) 배포 — 처음부터 만드는 법

Render 무료 플랜은 **팀원 초대가 되지 않습니다**(유료 Pro부터 가능). 그래서 소유자(팀장) 계정으로 한 번 만들고, 이후에는 코드가 합쳐질 때 자동 배포됩니다.

### 4-1. 서비스 만들기 (한 번만)

Render → **New + → Web Service** → GitHub 저장소 `haru2014/pet_walk_t01` 선택 후 아래 값을 넣습니다.

| 칸 | 값 |
|---|---|
| Name | `pet-walk-t01` (이름이 주소가 됩니다) |
| Region | Singapore |
| Branch | `main` |
| **Root Directory** | `backend` |
| Runtime | Python 3 |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn main:app --host 0.0.0.0 --port $PORT` |
| Instance Type | Free |

### 4-2. 환경변수 (Render의 Environment 탭)

| 이름 | 값 | 비고 |
|---|---|---|
| `PYTHON_VERSION` | `3.11.9` | 안 넣으면 더 새로운 Python으로 설치되어 오류가 날 수 있음 |
| `SUPABASE_URL` | Supabase Project Settings → API의 URL | |
| `SUPABASE_KEY` | publishable 키 (`sb_publishable_…`) | |
| `SUPABASE_SERVICE_ROLE_KEY` | secret 키 (`sb_secret_…`) | **마스터키. 채팅·코드·git에 올리지 말 것** |
| `ORS_API_KEY`, `GEMINI_API_KEY` | (선택) | 비어 있어도 서버는 켜짐 (§8) |

### 4-3. 자동 배포 설정

서비스 → Settings → Build & Deploy → **Auto-Deploy**를 **On Commit**으로 둡니다.

> **`After CI Checks Pass`는 쓰지 않습니다.** 우리 PR은 `github-actions` 로봇이 자동으로 합치는데, 로봇(GITHUB_TOKEN)이 합친 커밋은 GitHub 규칙상 `main`의 CI 검사를 새로 시작시키지 않습니다. 그러면 Render가 오지 않는 검사를 계속 기다려 배포가 시작되지 않습니다. (2026-10-15 실제로 발생, 합쳐진 커밋에 검사 기록이 없음) 검사 통과 보호는 PR 합치기 단계(`Auto Merge on CI Success`)에서 이미 적용됩니다.

```
PR 생성 → 자동 검사(CI) 통과 → main에 합쳐짐 → Render가 최신 코드로 자동 재배포
```

검사에 실패한 코드는 서버에 올라가지 않고, 이전 버전이 계속 동작합니다.

### 4-4. 배포가 잘 되었는지 확인 (1분)

1. `https://pet-walk-t01-z095.onrender.com/health` → `"status":"ok"`, `"supabase_connected":true`
2. 코스 요청이 실제로 동작하는지: 앱을 운영 주소로 연결한 뒤 코스를 만들고, 브라우저 개발자 도구(F12) → Network에서 `walk/plan`이 **200**인지 봅니다.
3. 새 코드가 반영됐는지 의심되면 잘못된 값을 보내 봅니다. (예: `origin_lat: 999` → 새 코드는 **400**)

### 4-5. 무료 플랜의 약점: 잠자기

- 한동안 요청이 없으면 서버가 잠들고, **첫 요청이 약 4~30초** 걸립니다. (2026-10-15 실측 4.2~4.8초)
- 앱은 서버가 3.5초 안에 답하지 않으면 **에러 없이 샘플 코스로 대체**합니다. 그래서 잠든 직후에는 샘플이 보일 수 있습니다.
- **시연·테스트 5분 전에 `/health` 주소를 한 번 열어 서버를 깨워 두세요.**

## 5. 환경변수(`.env`) 다루는 법

- `.env` 파일은 `.gitignore`에 들어 있어 **git에 올라가지 않습니다.** 그래서 내 컴퓨터의 `.env`가 다른 사람 컴퓨터에는 없습니다.
- 칸 이름은 저장소의 `.env.example`에 있고, **값의 원본은 Supabase 화면**(Project Settings → API)에 있습니다. 각자 거기서 복사해 만듭니다.
- 파일 두 개가 따로 있습니다.

| 파일 | 위치 | 들어가는 값 |
|---|---|---|
| 서버용 | 저장소 맨 바깥 `.env` | `SUPABASE_URL`, `SUPABASE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `ORS_API_KEY`, `GEMINI_API_KEY` |
| 앱용 | `frontend/.env` | `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`(=publishable 키) |

**보안 원칙**
1. `SUPABASE_SERVICE_ROLE_KEY`(secret 키)는 **서버 전용**입니다. 앱 코드·`frontend/.env`에 넣지 않습니다. (앱에는 publishable 키만)
2. 키는 디스코드·메일·스크린샷으로 주고받지 않습니다.
3. 유출이 의심되면 지우는 것이 아니라 Supabase에서 **재발급**합니다.
4. 앱을 폰용 빌드(EAS)로 만들 때 `frontend/.env`는 포함되지 않으므로, EAS 환경변수에 `EXPO_PUBLIC_API_URL=https://pet-walk-t01-z095.onrender.com`을 따로 넣어야 합니다.

## 6. DB(Supabase) 준비 순서

새 Supabase 프로젝트를 쓸 때 (이미 `pet_walk`에는 적용 완료):

1. Authentication → Providers → Email: Allow sign up **ON**, Confirm email **OFF**(CBT 기간 한정, 실서비스 전 ON으로 되돌리기)
2. Storage → 버킷 `pet-photos` 생성 후 **Private(비공개)** 확인 (새로 만들면 기본이 공개일 수 있음)
3. SQL Editor에서 순서대로 실행:
   - `backend/sql/supabase_schema.sql` (커뮤니티 코스·위험 제보)
   - `backend/sql/supabase_auth_schema.sql` (반려견 프로필·산책 기록·보안 규칙·사진 정책)
4. 표 4개(`community_courses`, `hazard_reports`, `dog_profiles`, `walk_records`)가 보이는지 확인

**DB 약속 요약** (자세한 내용은 [`../backend/sql/README.md`](../backend/sql/README.md))
- `id`는 UUID 형식입니다. 앱이 `crypto.randomUUID()`로 만들어 보냅니다. (`dog_123` 같은 글자 id는 DB가 400으로 거절)
- `user_id`는 로그인 계정의 id, 사진은 `pet-photos/<user_id>/…` 경로에 저장하고 DB에는 **경로만** 저장합니다.
- `walk_records.is_public`의 기본값은 `false`(비공개)입니다.
- 저장 오류(`{ error }`)를 무시하지 않습니다. (과거 id 형식 불일치 오류가 조용히 묻혀 데이터가 DB에 안 들어간 사례가 있었음)

## 7. 문제가 생겼을 때 (실제로 겪은 것들)

| 증상 | 원인 | 해결 |
|---|---|---|
| `No module named 'langgraph'` | 다른 가상환경에서 서버를 켬 | `.venv\Scripts\activate` 후 다시 실행 |
| `npm error ... package.json 을 찾을 수 없음` | `frontend` 폴더가 아닌 곳에서 실행 | `cd frontend` 후 `npm run web` |
| 앱 화면이 하얗고 `Unable to resolve module …` | `git pull`로 새 라이브러리가 추가됐는데 설치 안 함 | `frontend`에서 `npm install` |
| 코스가 나오는데 서버 계산인지 모르겠음 | 서버가 안 닿으면 앱이 **조용히 샘플로 대체** | F12 → Network에서 `walk/plan` 200 확인 (또는 서버 로그) |
| 첫 요청이 매우 느림, 샘플 코스가 보임 | Render 무료 서버가 잠듦 | `/health`를 먼저 열어 깨우기 |
| 앱 저장이 DB에 안 들어감 | 로그인 안 한 상태(게스트), 또는 id 형식 불일치 | 로그인 후 저장, 콘솔의 빨간 `400` 확인 |
| `supabase_connected: true`인데 저장 실패 | 이 값은 "연결 객체 생성"만 뜻함 | 실제 표를 읽어 확인 |
| 로컬 서버가 느림 (+2초) | `localhost` 사용 | `127.0.0.1` 사용 |
