# 작업 목표: 앱 UI를 디자인 시안 02번으로 개편

첨부한 디자인 시안 중 **docs\reference\UI개선\app_design_n2-1.png** 디자인을 기준으로 기존 앱 UI를 개편한다.

## 1. 사전 분석
- 기존 프로젝트의 프레임워크, 디렉터리 구조, 화면 구성, 내비게이션, 상태 관리 및 지도 구현 방식을 먼저 확인한다.
- 기존에 구현된 기능과 데이터 흐름을 유지하면서 UI를 변경한다.
- 구현 전에 수정 대상 파일과 변경 계획을 간략하게 제시한다.

## 2. 디자인 기준
- 메인 색상: Sage Green (#5A7361)
- 강조 색상: Dusty Amber (#CFA052)
- 보조 색상: Olive Ochre (#B59C5E)
- 일러스트 색상: Leaf Green (#8C9E7D)
- 배경 색상: Soft Cream (#F5EFE0)
- 카드: 밝은 크림색 또는 흰색, 부드러운 모서리, 절제된 그림자
- 전체 인상: 따뜻하고 친근하며 자연 친화적인 반려견 산책 앱

색상은 디자인 토큰으로 관리한다. 화면 곳곳에 개별 색상 코드를 중복 선언하지 않는다.

## 3. 화면 구성
1. 상단: 메뉴 아이콘, 알림 아이콘, 강아지 마스코트
2. 메인 카드: 강아지 캐릭터, 'Park Walk Mode' 제목, 지도 영역
3. 지도 카드 하단: 산책 거리와 시간 등 핵심 정보
4. 정보 카드: 'Trail info' 제목, 산책 관련 설명, 나무 일러스트
5. 하단 내비게이션: 기존 앱의 주요 메뉴와 이동 기능 유지

첨부 이미지를 단순한 배경으로 삽입하지 않는다. 각 요소를 실제 UI 컴포넌트로 구현한다.

## 4. 이미지 에셋
- 강아지 캐릭터와 나무 일러스트는 별도의 이미지 에셋으로 관리한다.
- 프로젝트에 적합한 PNG 또는 SVG 형식을 선택한다.
- 첨부한 시안에서 개별 그림을 추출할 수 있다면 우선 활용 가능성을 검토한다. 단, 화면 프레임, 그림자, 다른 UI 요소가 섞인 이미지를 최종 에셋으로 사용하지 않는다.
- 필요한 에셋이 없으면 임시 대체 요소를 적용하고, 필요한 이미지의 파일명·크기·배경 투명 여부·사용 위치를 목록으로 작성한다.
- 존재하지 않는 이미지 파일을 참조하거나 이미지 경로를 임의로 가정하지 않는다.

## 5. 기능 및 구현 제약
- 지도, 위치, 산책 시작, 거리·시간 표시, 알림, 하단 내비게이션 등 기존 기능을 유지한다.
- 지도와 산책 경로를 정적 이미지로 대체하지 않는다.
- 기존 API, 데이터 모델, 인증, 상태 관리 및 화면 이동을 임의로 제거하지 않는다.
- 화면에 표시되는 텍스트와 데이터는 기존 앱의 실제 데이터 흐름을 활용한다.
- 반응형 레이아웃과 접근성을 고려하고, 작은 화면에서 텍스트나 버튼이 잘리지 않도록 한다.
- 기존 프로젝트의 기술 스택과 코딩 규칙을 따른다. UI 변경만을 위해 불필요한 라이브러리를 추가하지 않는다.
- 현재 앱이 Expo/React Native 프로젝트라면 Android Studio용 Jetpack Compose 코드를 생성하지 않도록 한다.

## 6. 구현 및 검증
- 디자인 토큰, 공통 컴포넌트, 화면 UI 순으로 구현한다.
- 실제 앱 또는 개발 미리보기에서 첨부 시안과 비교한다.
- 색상, 여백, 카드 크기, 이미지 비율, 타이포그래피 및 내비게이션을 보정한다.
- 기존 테스트와 빌드 검증을 수행한다.
- 완료 후 변경 파일, 구현된 기능, 사용한 이미지 에셋, 미완료 항목 및 테스트 결과를 보고한다.

우선 프로젝트 구조를 분석하고 구현 계획을 제시한다. 분석 후에는 기존 기능을 보존하는 범위에서 실제 코드 변경을 진행한다.
