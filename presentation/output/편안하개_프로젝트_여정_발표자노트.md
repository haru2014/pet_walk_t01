### Slide 01. 표지 (편안하개: 시작부터 완성까지의 개발 여정)
> "안녕하십니까, AI Native 반려견 맞춤형 안심 노면 산책 플랫폼 **'편안하개'**의 성과 발표를 맡은 팀 편안하개입니다.  
> 저희 프로젝트의 기획과 설계 기준은 `docs` 폴더에 체계적으로 기록되어 있고, 그 문서를 실제로 구현하며 치열하게 고민하고 부딪힌 여정은 `GitHub`의 831개 커밋과 331개의 PR, 82개의 이슈 속에 온전히 녹아 있습니다.  
> 오늘 발표에서는 기획 문서에서 출발하여 GitHub을 거쳐 실제 동작하는 완성도 높은 앱 서비스로 탄생하기까지의 전 과정을 투명하고 생생하게 소개해 드리겠습니다."

### Slide 03. [시작 1/3] 문제 정의와 제품 가설의 출발 (Docs)
> "모든 프로젝트의 시작은 '풀고자 하는 문제가 무엇인가'라는 질문에서 시작됩니다. 저희는 `docs/04` AI 문제 정의서와 `docs/06` 제안서를 통해 반려견 보호자들이 매일 겪는 세 가지 고통을 정의했습니다.  
> 첫째, 반려견 관절을 위협하는 계단과 15도 급경사, 여름철 아스팔트 지면열을 사전에 알 수 없다는 점입니다.  
> 둘째, 길을 찾느라 스마트폰 화면에 시선이 뺏겨 자전거나 다른 맹견과의 돌발 충돌에 무방비해진다는 점입니다.  
> 셋째, 노령견이나 슬개골 취약견처럼 반려견마다 체급과 건강 조건이 다른데도 기존 지도 앱은 사람 중심의 최단거리만 추천한다는 점입니다.  
> 저희는 '계단을 피하고, 화면을 보지 않고 음성으로 걸으며, 내 반려견에 맞춘 안심길을 걷는다'는 가설을 세우고 개발에 착수했습니다."

### Slide 04. [시작 2/3] 5인 엔지니어의 전문 영역 분담과 R&R (Docs)
> "명확한 문제를 풀기 위해 다섯 명의 엔지니어가 전문 영역을 나누었습니다. `docs/02` 팀 빌딩 문서에 정의된 R&R입니다.  
> 1번 조현정 PM은 요구사항 관리와 LangGraph ReAct 에이전트 오케스트레이션을 총괄했습니다.  
> 2번 전황진 님은 OpenStreetMap 보행망 태깅과 국토정보플랫폼 DEM 경사도, 기상청 지면온도 수지식을 맡았습니다.  
> 3번 노희선 님은 FastAPI 기반 백엔드, OSRM 라우팅 어댑터, 1.5초 SLA 캐시 레이어를 구축했습니다.  
> 4번 김승현 님은 React Native/Expo 기반 모바일 앱, 백그라운드 GPS 및 음성 안내 엔진, 무선 OTA 배포를 담당했습니다.  
> 5번 김정님 님은 긍정적 웰니스 UI 컴포넌트, 프론트엔드 전수 검증, 그리고 5인 실사용자 CBT 설계를 주도했습니다.  
> 저희의 협업은 개별 모듈에 갇히지 않고, 엄격한 API 스키마와 통합 시나리오를 통해 하나로 연결되었습니다."

### Slide 08. [여정 3/4] GitHub 이슈로 본 4대 핵심 난제 극복기 (GitHub)
> "실제 제품을 만드는 과정은 예상치 못한 난제와의 싸움이었습니다. GitHub Issue로 투명하게 관리한 대표적 4가지 극복 사례입니다.  
> 첫째, Issue #22 도심 빌딩 관통 버그입니다. 초기 라우팅이 단순 직선 보간으로 아파트 단지와 빌딩을 뚫고 지나가는 문제가 있었습니다. 이를 해결하기 위해 OSRM 실제 보행 도로망 기반 정밀 라우팅 엔진으로 전면 교체했습니다.  
> 둘째, Issue #28 응답 지연 병목입니다. 10개 지점 순차 계산으로 4.8초가 걸리던 것을 OSRM 병렬 호출과 10분 인메모리 반경 캐싱을 적용해 Warm P95 112.55ms로 40배 이상 단축했습니다.  
> 셋째, Issue #221/222 다크 포켓 모드 오류입니다. 주머니 속 시선 해방 모드를 해제할 때 화면이 튕기는 현상을 네비게이션 상태 머신 재설계로 바로잡았습니다.  
> 넷째, Issue #227 맹견 출몰 제보입니다. 공원 내 들개 출몰 시 일반 공사 구역으로 처리되던 문제를 바로잡아 'dog_danger' 위험 타입을 신설하고 라우팅 시 해당 구역을 자동 우회하도록 개선했습니다."

### Slide 09. [여정 4/4] 4주차 실사용자 CBT와 무선 OTA 핫픽스 (GitHub)
> "4주차 야외 필드 CBT는 제품의 완성도를 현장 실증 수준으로 끌어올린 결정적 순간이었습니다.  
> PR #328과 #329에서는 '차가 적은 길' 옵션 활성화 시 간선도로 버퍼를 25m/35m로 확장하고 횡단 페널티를 대폭 강화하여 도로 인접 경로를 원천 차단했습니다.  
> PR #329에서는 회전 30m 전 사전 음성 안내 타이밍과 15m 오차 보정을 연동해 음성 누락을 없애고, 실시간 나침반 마커 회전과 마이페이지 공유 상태(`isPublic`) 영속화를 완료했습니다.  
> PR #330에서는 산책 체감 후기 수정 시 태그 토글 첫 단어가 잘리던 정규식 버그를 근본 해결하고, 홈 날씨 상세 모달의 로딩 정합성을 완벽히 동기화했습니다."

### Slide 10. [여정 5/4] 엄격한 PR 코드 리뷰와 TDD 품질 가드레일 (GitHub)
> "어떻게 331개의 PR을 단 하나의 치명적 배포 사고 없이 메인에 머지할 수 있었을까요?

## ❓ 3. 예상 질문 및 기술적 답변 가이드 (Q&A Matrix)

### Q1. OSRM과 ORS 라우팅 어댑터에서 계단을 어떻게 완전히 배제했나요?
- **답변 요약**: OSM 원천 데이터의 `highway=steps` 태그 링크를 라우팅 그래프 구축 시 하드 필터링(`stairs.py`)하여 후보 경로 생성 단계에서 원천 차단했습니다. 또한 국토정보플랫폼 DEM 고도 래스터를 오버레이하여 링크별 종단 경사각을 계산하고, 15도 이상 구간에 대해 높은 페널티 가중치를 부여했습니다.

### Q2. Local-First 구조에서 커뮤니티 공유 시 자택 위치가 어떻게 보호되나요?
- **답변 요약**: `spatial_masking.py` 알고리즘을 통해 사용자가 기록한 GPS 궤적의 출발지와 도착지 반경 200m 구간 좌표를 완전히 절단(Truncate)하고, 최근접 보행 간선 교차로 노드로 스냅한 후 서버 DB에 등록합니다. 따라서 공개 피드에서는 견주의 자택 위치를 절대 유추할 수 없습니다.

### Q3. 112ms라는 초저지연 라우팅은 어떻게 달성했나요?
- **답변 요약**: 초기 4.8초 병목(Issue #28)은 10개 후보 지점을 순차 호출하던 구조 때문이었습니다. 이를 비동기 `asyncio.gather` 병렬 호출로 전환하고, 5대 파일럿 거점 공원 보행망과 기상 데이터를 10분 TTL 인메모리 반경 캐싱 처리하여 Warm 상태에서 112.55ms로 40배 이상 속도를 혁신했습니다.

### Q4. 331개의 많은 PR을 관리하면서 코드 품질을 유지한 비결은 무엇인가요?
- **답변 요약**: 철저한 CI/CD 자동화와 TDD 원칙입니다. 모든 기능 브랜치에서 단위 테스트가 먼저 작성되었고, GitHub Actions를 통해 Vitest(638건)와 Pytest(991건), TypeScript Strict 린트가 100% 통과되어야만 머지되었습니다. 또한 SonarLint 규칙에 따라 단일 컴포넌트 크기를 250줄 이하로 엄격히 제한했습니다.
