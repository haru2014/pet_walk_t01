# 편안하개 홈 화면 UX 개선안
## Gemini Code Assist 구현 전달 문서

- 대상: 편안하개(PetWalk) 모바일 앱 홈 화면
- 목적: 기존 브랜드 스타일과 기능을 유지하면서 정보 위계, 카드 밀도, 하단 콘텐츠 가시성, 주간 산책 그래프의 이해도를 개선한다.
- 구현 원칙: **기존 동작과 데이터 로직을 보존하고 UI/레이아웃을 우선 개선한다.** 실제 프로젝트 구조와 사용 중인 컴포넌트를 먼저 확인한 뒤 변경한다.

---

## 1. 개선 목표

1. 홈 화면의 시각적 우선순위를 `산책 시작 → 산책 환경 판단 → 주간 목표 확인` 순서로 정리한다.
2. 카드 내부의 중복 설명과 과도한 여백을 줄여 첫 화면에서 더 많은 핵심 정보를 보여준다.
3. 고정 하단 내비게이션과 Android 시스템 내비게이션 영역이 스크롤 콘텐츠를 가리지 않도록 한다.
4. 주간 산책 달성도에서 목표, 실제 기록, 오늘, 기록 없음, 미집계 상태를 명확히 구분한다.
5. 기존 민트·그린 컬러, 둥근 카드, 반려견 친화적 브랜드 분위기는 유지한다.
6. 접근성, 반응형 레이아웃, 작은 화면, 큰 글씨 설정에서도 사용성을 유지한다.

## 2. 구현 전 점검

코드를 수정하기 전에 다음을 확인한다.

- 홈 화면을 구성하는 화면 파일과 하위 컴포넌트
- 하단 탭 내비게이션이 화면 내부에 있는지, 네비게이터 레이아웃에 있는지
- Safe Area 처리 방식 및 `react-native-safe-area-context` 사용 여부
- 스크롤 컨테이너 종류(`ScrollView`, `FlatList` 등)
- 반려견 카드의 다중 반려견 전환 방식과 현재 표시 문구
- 지면 온도·추천 시간대 데이터의 출처, 갱신 주기, 시간대 상태 판정 로직
- 주간 산책 집계의 데이터 구조, 주 시작 요일, 시간대, 목표 횟수 계산 방식
- 기존 디자인 토큰, 색상 상수, 공통 카드·버튼 컴포넌트
- 기존 테스트와 린트/타입 검사 명령

기존 기능이나 데이터 흐름을 추측해서 재작성하지 않는다. 데이터가 실제로 없는 경우 임의의 값이나 더미 기록을 운영 화면에 넣지 않는다.

## 3. 목표 화면 구조

홈 콘텐츠는 다음 순서로 배치한다.

1. **앱 헤더**: 앱 아이콘/이름, 알림, 더보기
2. **인사말 및 페이지 제목**: 짧고 명료하게
3. **반려견 산책 카드**: 반려견 정보와 주요 CTA
4. **지면 온도/추천 산책 시간 카드**: 현재 상태와 추천 시간대
5. **이번 주 산책 카드**: 주간 목표 진행률, 요일별 실적, 핵심 통계
6. **최근 산책 영역**: 최근 기록 또는 기록이 없을 때의 안내
7. **고정 하단 내비게이션**: 홈, 산책, 커뮤니티, 마이

화면의 실제 높이에 따라 일부 카드가 첫 화면 아래로 이어지는 것은 허용한다. 다만 고정 내비게이션에 콘텐츠가 가려지거나, 마지막 항목까지 스크롤할 수 없는 현상은 없어야 한다.

## 4. 컴포넌트별 변경 요구사항

### 4.1 반려견 산책 카드

**목표:** 사용자가 반려견 상태와 산책 시작 동작을 빠르게 파악하게 한다.

- 반려견 이미지/아바타, 이름, 준비 상태를 한 영역에 간결하게 배치한다.
- 품종, 나이, 평균 속도는 보조 정보로 한 줄 또는 적절한 줄바꿈으로 표시한다.
- `산책 시작` 버튼을 카드 내 가장 강조되는 주요 CTA로 유지한다.
- 버튼의 기존 산책 시작 로직, 이벤트, 권한 확인, 이동 경로는 변경하지 않는다.
- `30분 산책`, `폭신한 길 우선` 같은 설정값은 작은 칩으로 정리한다. 텍스트가 잘리거나 칩이 좁은 화면에서 화면 밖으로 나가지 않도록 한다.
- `1/3 ↔`처럼 의미가 모호한 표기는 가능하면 `1/3마리` 등 명확한 문구로 개선한다. 다중 반려견 전환 기능은 기존 방식대로 유지하고, 전환 가능함을 시각적으로 알린다.
- 준비 완료 상태는 색상만으로 표현하지 말고 텍스트를 함께 제공한다.
- 프로필 이미지를 누르는 동작과 산책 시작 버튼 동작이 서로 충돌하지 않도록 터치 영역을 분리한다.

### 4.2 지면 온도 및 추천 산책 시간 카드

**목표:** 온도, 안전 관련 안내, 추천 시간대를 빠르게 이해하게 한다.

- 제목을 짧게 정리한다. 예: `산책하기 좋은 지면 온도`
- 현재 지면 온도를 카드의 핵심 정보로 시각적으로 강조한다.
- 온도에 대한 설명은 한 문장으로 압축한다.
- 추천 산책 시간대는 타임라인/진행 막대 형태로 보여주되, 시작·종료 시각을 명확히 표시한다.
- 현재 시각이 추천 시간대 안인지, 이미 지났는지, 아직 시작 전인지 상태를 구분한다.
- 현재 시각과 추천 시간대의 비교 로직은 기존 데이터를 사용한다. 시간대 상태를 UI에서 임의로 계산해 기존 비즈니스 로직과 불일치시키지 않는다.
- 카드의 상세 정보가 필요하면 `자세히 보기`와 같은 명시적인 이동 동작을 제공한다.
- 지면 온도 데이터가 없거나 오래된 경우에는 임의의 정상 온도를 표시하지 말고 로딩/오류/갱신 시각 등 기존 정책에 맞는 상태를 제공한다.
- 안전을 과도하게 단정하는 표현은 피하고, 기존 앱의 안전 정책과 데이터 기준을 따른다.

### 4.3 이번 주 산책 달성도 카드

**목표:** 주간 목표 달성 상황과 요일별 산책 실적을 즉시 파악하게 한다.

카드 상단:
- 제목: `이번 주 산책`
- 기간 표시: 현재 앱의 주간 집계 기준에 맞는 시작일–종료일
- 주간 목표: 예를 들어 `0/5회`
- 진행률: 예를 들어 `0%`
- 제목 영역에 목표와 진행률을 간결하게 배치한다.

그래프:
- 요일별 막대 그래프를 사용하고, 각 요일 라벨을 표시한다.
- 막대가 나타내는 지표를 명시한다. 예: `요일별 산책 횟수` 또는 `요일별 산책 시간`.
- 횟수 그래프라면 축/레이블/막대가 횟수를 나타내도록 일관되게 구성한다. 횟수와 시간을 한 그래프에서 혼합하지 않는다.
- 실적이 0인 날짜는 실제 집계가 완료된 경우 `0회`로 표시할 수 있다.
- 미래 날짜 또는 아직 집계되지 않은 날짜는 `0회`와 구별해 `—` 또는 미집계 상태로 표현한다.
- 오늘은 `오늘` 라벨 및 일관된 강조 색상/테두리로 구분한다. 현재 화면에서 오늘이 아닌 요일을 임의로 강조하지 않는다.
- 목표 기준선을 표시할 경우 해당 선의 의미를 텍스트 또는 범례로 설명한다.
- 그래프는 색상만으로 정보를 전달하지 않으며 텍스트와 형태를 함께 사용한다.
- 그래프가 접근성 트리에서 의미 있는 요약을 제공하도록 한다. 예: `월요일 산책 1회`, `화요일 기록 없음`.
- 데이터가 없을 때 가짜 막대/실적을 렌더링하지 않는다. 빈 상태 안내와 그래프의 정상적인 0값을 구분한다.

하단 통계:
- 누적 거리, 산책 시간, 완만 노면 비율은 작은 통계 영역으로 간결하게 표시한다.
- 각 수치의 단위(`km`, `분`, `%`)를 반드시 표시한다.
- `완만 노면 88%`의 집계 대상과 기준이 실제 데이터 정의와 일치하는지 확인한다.
- 산책 기록이 없는데 완만 노면 비율이 0이 아닌 값으로 표시되는 경우, 이 값이 추천 경로 예상치인지 실제 산책 기록 기반인지 확인하고 라벨을 명확히 한다.
- 세부 통계는 `주간 통계 보기` 등 명확한 CTA를 통해 상세 화면으로 이동시킨다.
- 기존 탭/클릭 동작이 있다면 유지한다.

### 4.4 최근 산책 영역

- 최근 산책 카드는 주간 달성도 아래에 배치한다.
- 기록이 있으면 기존 데이터와 상세 화면 이동 동작을 유지한다.
- 기록이 없으면 빈 상태 안내와 다음 행동을 제공한다. 예: `아직 산책 기록이 없어요. 지금 산책을 시작해 보세요.`
- 기록이 없다는 이유로 샘플 기록을 추가하지 않는다.
- 고정 하단 내비게이션에 카드 제목, 본문, 버튼이 가려지지 않도록 한다.

## 5. 하단 영역 및 Safe Area — 필수 수정

첨부 화면에서 가장 먼저 해결해야 할 문제다. 주간 달성도 카드와 최근 산책 영역이 하단 내비게이션에 가려지지 않도록 한다.

### 요구사항

1. 본문 스크롤 영역과 고정 하단 내비게이션을 구조적으로 분리한다.
2. 하단 내비게이션은 기존처럼 고정하되, 본문 콘텐츠 위에 불투명한 영역으로 겹쳐 콘텐츠를 가리는 구조를 피한다.
3. 스크롤 콘텐츠의 `paddingBottom`은 하단 내비게이션의 실제 높이와 필요한 간격을 고려한다.
4. Android 시스템 하단 인셋/제스처 영역을 반영한다.
5. Safe Area 인셋을 두 번 더해 과도한 공백이 생기지 않도록 한다.
6. 화면을 끝까지 스크롤하면 최근 산책 카드의 마지막 콘텐츠가 하단 탭 위로 완전히 올라와야 한다.
7. 작은 화면, 가로 방향(앱이 지원하는 경우), 큰 글씨/접근성 글꼴에서도 겹침이 없어야 한다.

### React Native 구현 참고

- 프로젝트가 이미 `react-native-safe-area-context`를 사용한다면 기존 패턴에 맞춰 적용한다.
- 고정 탭 내비게이션의 높이를 하드코딩하기보다 기존 레이아웃 상수나 실제 네비게이터 구조를 활용한다.
- `ScrollView`/`FlatList`의 `contentContainerStyle`에 적절한 하단 여백을 둔다.
- `position: 'absolute'`를 쓰는 하단 메뉴라면 콘텐츠 영역의 하단 패딩과 시스템 인셋을 명시적으로 처리한다.
- 네비게이터 자체가 탭 바 공간을 이미 확보한다면 같은 높이를 중복으로 추가하지 않는다.
- 화면 전체를 임의의 고정 높이로 제한하거나, 콘텐츠를 잘라서 겹침을 숨기는 방식은 사용하지 않는다.

## 6. 시각 디자인 가이드

기존 편안하개 디자인 언어를 유지한다.

### 권장 간격의 시작값

| 항목 | 권장 시작값 | 참고 |
|---|---:|---|
| 화면 좌우 여백 | 20–24dp | 작은 화면에서는 유연하게 조정 |
| 카드 내부 여백 | 16–20dp | 카드 정보량에 따라 조정 |
| 카드 사이 간격 | 12–16dp | 모든 카드에서 일관성 유지 |
| 주요 버튼 높이 | 48–56dp | 터치 접근성 고려 |
| 칩 높이 | 약 32–40dp | 글자 잘림 방지 |
| 본문 글자 | 기존 디자인 토큰 사용 | 공간 확보를 위해 과도하게 축소하지 않음 |

위 값은 시작점이며, 실제 화면과 기존 디자인 시스템을 확인한 뒤 조정한다.

### 시각적 위계

1. **주요 행동:** `산책 시작` — 가장 높은 대비와 충분한 터치 영역
2. **안전 판단:** 현재 지면 온도 및 추천 시간대
3. **주간 진행:** 주간 목표, 진행률, 요일별 실적
4. **보조 정보:** 품종/나이/속도, 누적 거리/시간 등

### 스타일 원칙

- 기존 민트/그린 브랜드 컬러를 유지한다.
- 모든 카드에 진한 테두리와 강한 그림자를 동시에 적용하지 않는다.
- 기본 카드는 얕은 그림자 또는 미세한 구분선으로 정리한다.
- 강조 색상은 주요 CTA, 진행률, 오늘 상태 등 제한된 의미에 사용한다.
- 아이콘, 칩, 제목, 수치의 크기와 간격을 일관되게 유지한다.
- 중요한 상태는 색상뿐 아니라 텍스트로도 표현한다.
- 기존 Pretendard 등 프로젝트의 실제 폰트 설정과 토큰을 우선 사용한다.

## 7. 상태 및 예외 처리

아래 상태를 실제 데이터 흐름에 맞게 확인한다.

- 반려견이 한 마리인 경우 / 여러 마리인 경우
- 반려견 정보가 불완전한 경우
- 지면 온도 로딩 중 / 오류 / 데이터 없음 / 오래된 데이터
- 추천 시간대 시작 전 / 진행 중 / 종료 후
- 주간 산책 실적 0회 / 일부 달성 / 목표 달성 / 목표 초과
- 오늘 날짜 / 미래 날짜 / 집계 완료된 과거 날짜
- 최근 산책 기록 존재 / 기록 없음
- 작은 화면 / 큰 글꼴 / 하단 제스처 내비게이션 / 3버튼 내비게이션

모든 상태에서 레이아웃이 튀거나 겹치지 않도록 한다.

## 8. 테스트 및 완료 기준

### 기능 회귀

- [ ] 산책 시작 버튼이 기존과 동일하게 동작한다.
- [ ] 반려견 전환이 기존과 동일하게 동작한다.
- [ ] 산책 시간/경로 선호 설정이 올바르게 표시된다.
- [ ] 지면 온도와 추천 시간대가 기존 데이터와 일치한다.
- [ ] 주간 집계 기간, 목표 횟수, 진행률 계산이 기존 기준과 일치한다.
- [ ] 주간 통계 및 최근 산책 상세 이동이 유지된다.

### 레이아웃

- [ ] 하단 내비게이션이 콘텐츠를 가리지 않는다.
- [ ] 스크롤 끝에서 최근 산책 카드 전체를 볼 수 있다.
- [ ] Safe Area가 정확히 적용되고 하단 공백이 과도하지 않다.
- [ ] 긴 반려견 이름과 긴 문구가 레이아웃을 깨뜨리지 않는다.
- [ ] 작은 화면과 큰 글씨에서도 버튼/텍스트가 잘리지 않는다.
- [ ] 로딩/오류/빈 상태가 정상 표시된다.

### 그래프

- [ ] 그래프 지표가 횟수인지 시간인지 명확하다.
- [ ] 0회와 미집계/미래 날짜가 구분된다.
- [ ] 오늘 표시가 실제 날짜와 일치한다.
- [ ] 실제 기록이 없을 때 더미 실적을 표시하지 않는다.
- [ ] 단위와 접근성 설명이 제공된다.
- [ ] 주간 목표 및 진행률이 그래프/집계 데이터와 일치한다.

### 품질 검사

프로젝트에서 이미 사용하는 명령을 기준으로 실행한다.

- [ ] 관련 단위 테스트 및 UI 테스트
- [ ] TypeScript 검사
- [ ] ESLint 또는 프로젝트 린트
- [ ] Android 빌드 또는 개발 실행 확인(가능한 경우)

실행하지 못한 검사는 완료된 것처럼 보고하지 않는다.

## 9. 구현 작업 순서

1. 기존 홈 화면 구조, 스타일 토큰, 데이터 모델, 하단 내비게이션 구조를 조사한다.
2. 현재 UI 동작과 집계 로직을 보존한 채 반려견 카드와 지면 온도 카드를 재배치한다.
3. 주간 달성도 카드의 정보 위계와 그래프 상태 표현을 개선한다.
4. 스크롤 영역, 고정 하단 내비게이션, Safe Area 및 하단 패딩을 수정한다.
5. 최근 산책 영역과 빈 상태를 정리한다.
6. 다양한 데이터 상태와 화면 크기로 테스트한다.
7. 관련 검사/테스트를 실행하고 수정 파일, 변경점, 실행 결과, 남은 이슈를 요약한다.

## 10. Gemini Code Assist에 대한 최종 지시

첨부된 기존 홈 화면을 기준으로 이 문서의 개선 사항을 구현한다. 기존 기능, API, 데이터 모델, 네비게이션, 산책 기록 계산을 임의로 재작성하지 않는다. 먼저 실제 코드 구조를 확인하고 변경 범위를 최소화한다. 시각적 변경이 목적이므로 백엔드 계약이나 저장 형식을 바꾸지 않는다. 구현 후 수정 파일 목록, 주요 변경 사항, 테스트 결과, 미해결 항목을 보고한다.
