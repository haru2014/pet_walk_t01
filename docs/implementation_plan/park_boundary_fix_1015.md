# 지정 공원 경로 이탈 수정 결과 (2026-10-15)

`backend_improvement_plan_1015_updated.md`의 P0/P1 안전 차단과 파일럿 공원 내부 그래프 라우팅을 구현했다.

## 확인된 원인

- 기존 송강 좌표열은 일부 곁가지를 잘라내도 실제 공원 경계 밖이다. 기존 중심 `(36.4315, 127.3805)`도 실제 송강공원 보행망과 떨어져 있다.
- 기존 경계 파일은 원본 출처·버전이 없었다. 검사에서는 여기에 `buffer(0.0005)`를 더해 외부 구간까지 허용했다.
- `_plan_variant`는 공원 정적 코스가 없으면 일반 OSRM 결과를 경계 검사 없이 반환했다.
- 후보 중복 대체 분기는 모드에 관계없이 서울 정적 코스를 적용할 수 있었다.
- API는 최우선 후보의 좌표 유무만 확인했고, 나머지 추천 후보에는 독립 검증이 없었다.
- 앱은 422, 타임아웃, 네트워크 장애를 로컬 샘플 코스로 대체했다. 추천 화면도 서버 검증 전에 샘플 코스를 표시하고 시작할 수 있었다.

이 항목들은 코드와 로컬 API 회귀 테스트로 확인했다. 운영 서버의 기존 요청 로그를 확보하거나 운영 배포를 변경한 것은 아니다.

2026-10-15 OpenStreetMap map API로 수집했다. 좌표계는 EPSG:4326, 좌표 순서는 `[경도, 위도]`이다. 경계와 보행망은 별도 fixture에 저장하고 출처·원본 버전·조회일을 기록했다. OSM 기반 검증이며 현장 실측이나 법적 지적 경계 보증을 뜻하지 않는다. 저작자 표시: © OpenStreetMap contributors, ODbL-1.0.

송강공원 형상 범위는 경도 `127.3837777~127.3857761`, 위도 `36.4345997~36.4361236`이다. 공원 이름과 주소는 [문화체육관광부 작은도서관 목록의 송강마을 작은도서관](https://www.mcst.go.kr/slibrary/library/index?currentPage=415&searchGugun=&searchLibraryName=&searchSido=)에 기재된 송강근린공원 내 주소와 대조했다.

갱신 명령:

```powershell
python backend/scripts/import_pilot_park_osm.py
```

이후 테스트를 실행하고 서버를 다시 시작한다. 실행 중 매 요청마다 외부 지도 서비스를 호출하지 않는다. 조회에 실패하거나 정확한 이름의 단일 경계가 없으면 실제 경계를 임의로 합성하지 않는다.

## 구현한 보장

1. `park`/`parking_pnr` 모드는 검증된 공원 경계 안에 완전히 들어가는 OSM 보행 간선만 사용한다. 계단, 보행 금지·비공개 접근 간선은 제외한다.
2. 출발점에서 100m 이내의 보행 노드에 스냅하고 같은 연결 컴포넌트의 순환로만 탐색한다. 존재하지 않는 연결을 직선으로 추가하지 않는다. 스냅 좌표와 거리는 응답에 기록한다.
3. 동일한 실제 순환로는 최대 네 번까지 반복할 수 있다. 목표 시간보다 크게 짧으면 내부 대안 코스라고 안내한다. 경계 밖 우회로를 추가하지 않는다.
4. `Polygon`/`MultiPolygon`과 hole을 포함해 전체 선분을 검사한다. 경계선 접촉은 허용하지만 경계 버퍼는 0m다.
5. 최종 API 게이트는 최우선 후보와 모든 대안을 독립적으로 검사한다. 실패 후보를 제거하고 유효한 대안을 선택한다. 전부 실패하면 경로 없이 422를 반환한다.
6. 응답 거리와 시간은 최종 좌표열과 요청된 보행 속도로 재계산한다. 목표 시간의 125%를 초과한 후보는 거부한다. 이는 파일럿 초기 정책이며 보편적 보행시간 보장은 아니다.
7. 성공 응답에 `request_id`, `validated_park_id`, 후보별 `route_validation`을 추가한다. 실패 응답은 기존 문자열 `detail`을 유지하고 `code`, `request_id`를 추가한다. 요청·후보 검증·실패·완료를 JSON 로그로 추적한다.
8. 앱은 공원 모드에서 검증 메타데이터가 없는 구버전 서버 응답도 거부한다. HTTP 오류·네트워크 실패·미등록 공원은 샘플 코스로 대체하지 않는다. 추천 화면은 검증 완료 후에만 경로·대안·산책 시작을 표시한다.

## 회귀 검증

- 송강공원 40분, 2.8km/h 요청: 최우선 코스 약 **1,639m / 35.1분**. 모든 반환 코스의 전체 선분이 실제 경계 안의 보행 간선에 속하고 출발점으로 복귀한다.
- 기존 송강 좌표열, 다른 공원으로의 암묵적 변경, 공원 밖 출발점, hole을 가로지르는 선분, MultiPolygon 사이 점프, 끊긴 보행망, 누락·손상 경계, 보행망 누락, 임의 OSRM/직사각형 폴백, 잘못된 대안 코스, 메타데이터 불일치, 시간 초과를 회귀 테스트로 검사한다.
- 주차장 좌표가 내부 보행망에서 멀거나 공원 경계가 미확인인 P&R 요청도 검증을 우회하지 않는다. 기존 잘못된 주차장 좌표는 임의로 수정하지 않고 오류를 반환한다.
- 프런트엔드 API 테스트는 422와 장애에서 샘플 경로가 반환되지 않는지, 모든 대안의 검증이 확인되는지 검사한다.
- 백엔드 전체 471개, 프런트엔드 전체 248개 테스트 통과 후 미등록 공원 차단 테스트를 추가해 관련 14개를 다시 통과했다. 타입 검사와 변경 파일 린트가 통과했으며 전체 린트에는 기존 경고 12개만 남아 있다.

## 남은 범위와 배포 조건

- 세종·도안은 신뢰할 경계와 보행망을 추가하기 전까지 지정 공원 코스를 반환하지 않는다.
- 전국 공원 검색, PostGIS 저장소, 현위치→공원 접근→복귀 라우팅은 후속 P2/P3 범위다. 현위치 모드의 기존 라우팅 정책은 이번 변경 대상이 아니다.
- 기존 즐겨찾기·커뮤니티 코스는 새로 생성하는 지정 공원 요청과 별도 경로다. 기존 저장 데이터를 자동으로 안전 인증하지 않는다.
- 백엔드와 앱을 함께 배포해야 새 경계/검증 계약을 사용할 수 있다. 새 앱이 구버전 서버를 호출하면 검증 부재를 안내한다. `/health.commit`과 `request_id`로 실제 호출 서버를 확인할 수 있다.
- 운영 좌표 로그의 접근 권한·보관 기간 및 공간 데이터 갱신 주기는 운영 설정에서 별도로 관리해야 한다.
