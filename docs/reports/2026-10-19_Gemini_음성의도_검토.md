# Gemini 음성 의도 및 산책 설정 연결 검토 — 2026-10-19

## 범위

US-A1 음성 의도 파싱과 기존 산책 설정 → `/api/v1/walk/plan` 연결을 보완한다.
원본 계획서는 `docs/implementation_plan/old/gemini_api_적용_계획.md`에 있다.
Gemini가 좌표를 직접 생성하는 기능이나 새 ReAct 도구 체인은 추가하지 않는다.

## 수정 내용

- 기존 응답 필드 `target_duration_minutes`, `prefer_cushion`은 유지한다.
  입력 별칭 `duration_minutes`, `prefer_soft_surface`도 지원한다.
  Pydantic strict 검증으로 잘못된 타입과 10~90분 범위 밖의 시간을 거절한다.
- 모델 브리핑의 금지 어휘를 Pydantic 검증에서 웰니스 안내로 교체한다.
  프론트엔드도 화면·TTS 전달 전에 정제하여 로컬 폴백 및 이전 서버 응답을 보호한다.
- 올림픽공원 등 미지원 공원명을 보존하고 유림공원으로 바꾸지 않는다.
  지원 공원 또는 현재 위치를 명시적으로 선택하기 전에는 산책 요청을 막는다.
  한밭수목원·엑스포 등 다른 장소를 유림공원으로 바꾸던 매핑을 제거한다.
- 음성 인식 종료 시 해당 인식 세션의 최신 발화를 사용한다.
  음성 조건이 false이면 기존 그늘·폭신한 길·계단 회피 칩도 해제한다.
- Gemini 후보 모델 순서는 유지하며 SDK 자동 재시도를 1회 시도로 제한한다.
  전체 모델 호출에 2,400ms 예산을 공유하고 남은 시간을 다음 요청의 timeout으로 전달한다.
  예산 소진 시 다음 모델 호출을 중단하고 로컬 파서로 전환한다.
  예외 로그에는 오류 종류만 남기고 클라이언트 연결을 닫는다.

## 운영 확인 및 남은 검증

동일 날짜 운영 서버의 `/api/v1/voice/intent`에 올림픽공원 예문을 보낸 결과
`data_source=gemini_live`, `model_used=gemini-3.5-flash-lite`를 확인했다.
30분·그늘 선호·올림픽공원은 추출되었고 `landmark_park_id=null`이었다.
이는 기존 배포의 Gemini 호출이 정상이라는 증거이며 이번 수정의 배포 검증은 아니다.
Render Environment 화면 자체는 확인하지 않았고 키 등록·변경·재배포는 수행하지 않았다.

프론트엔드 서버 요청은 기본 서버 3,000ms와 로컬 서버 1,500ms 타임아웃을 사용한다.
정규식 처리 시간과 네트워크 폴백 대기 시간은 다르며 사용자 응답을 '0초'로 보장하지 않는다.
SDK 예산은 네트워크 요청 timeout이며 초기화·응답 처리까지 포함한 엄격한 실시간 SLA는 아니다.

실기기 마이크·야외 STT·GPS 및 새 빌드의 전체 화면 여정은 별도 검증이 필요하다.
계획서의 Gemini ReAct 기반 날씨·주차장 도구 선택은 기존 API 조건 전달과 구분하며,
이번 변경으로 전체 ReAct 구현 완료를 주장하지 않는다.

역할별 검토: PM·AI는 무상태 JSON 계약과 금지 어휘 검증, 모바일은 음성·설정 전달,
UI는 미지원 공원 안내를 확인했다. GIS 경계·라우팅 엔진·RLS 변경은 없다.
