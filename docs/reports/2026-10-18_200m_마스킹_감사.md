# 200m 마스킹 감사 (US-G2, P1)

> 작성: 전황진 (데이터·GIS) · 기준: main `06b5330` · 작성일 2026-10-18
> 목적: 커뮤니티 공유의 출발·도착지 200m 마스킹이 실제로 자택 위치를 가리는지, 원본 위치가 다른 경로로 새지 않는지 확인한다.

## 1. 범위와 방법

| 대상 | 방법 |
|---|---|
| 마스킹 함수 `backend/agent/spatial_masking.py` (#33) | 가상 자택(대전 둔산동) 기준 경로 6종을 만들어 결과 경로의 자택 최소 거리를 잼 |
| 공유 API `POST /api/v1/community/share`, 피드 `GET /api/v1/community/feed` | 코드 확인. 저장·응답 필드 |
| Supabase 저장 (`community_courses`, `walk_records`), RLS (`backend/sql/supabase_auth_schema.sql`) | 코드·스키마 확인 |
| 앱 공유 흐름 (`WalkReportScreen` → `communityApi.shareCommunityCourse` → `apiClient`) | 코드 확인. 대체 서버, 실패 처리 |
| 서버 로그 (`main.py`) | 위치가 기록되는 로그 확인 |

## 2. 마스킹 함수 시험

| 경로 | 수정 전 | 수정 후 |
|---|---|---|
| 사각 순환 (집 출발·도착) | 남은 경로 집에서 400m 이상 | 같음 (변화 없음) |
| **중간에 집 앞을 다시 지나는 8자 경로** | **남은 경로가 집 53m까지 접근** | 재진입 구간 제거, 210m 이상 |
| 점 간격이 넓은 GPS | 260m 이상 | 같음 |
| 점은 반경 밖이지만 선분이 집 원을 가로지름 | 원 통과 | 선분에서 끊음, 300m 이상 |
| 같은 길 왕복 | 점 1개만 남음 (699m) | 같음 |
| 집 주변 300m 안 짧은 코스 | 점 1개만 남음 (213m) | 같음 |

## 3. 발견 사항과 조치

### 상 1. 경로 중간의 재진입이 공개됨 → 이번 PR에서 수정
- 원인: 출발 쪽·도착 쪽 끝만 자르고 중간 구간은 검사하지 않았다(`_find_boundary_cut_indices`).
- 조치: 끝을 자르고 교차로 스냅을 한 뒤 `_drop_reentry`로 한 번 더 거른다. 출발·도착지 200m 안의 점과 반경 원을 가로지르는 선분에서 경로를 끊고, 반경 밖의 가장 긴 연속 구간만 남긴다. 결과에 `reentry_removed_points`를 추가했다.
- 회귀 테스트: `test_spatial_masking.py::TestReentryAudit` (수정 전 실패, 수정 후 통과).

### 중 1. 운영 로그에 정확한 출발 좌표 기록 → 이번 PR에서 수정
- 원인: `/walk/plan`의 `walk_plan_requested` 로그가 `origin: [경도, 위도]`를 그대로 남겼다. 현재 위치 출발은 자택일 수 있다.
- 조치: `origin_approx`로 바꾸고 소수 둘째 자리(약 1km)로 줄였다. 회귀 테스트: `test_walk_plan_log_does_not_keep_the_exact_origin`.

### 중 2. 산책 기록 테이블의 공개 설정 (현재 미사용) → 담당자 공유
- `walk_records.route_coords`에 "실제 걸은 전체 좌표"를 저장하도록 설계돼 있다. `is_public = true`(후기 공유)인 행은 RLS `public_walk_reviews`로 누구나 읽을 수 있다.
- 지금은 업로드 함수 `SupabaseService.createWalkRecord`를 호출하는 곳이 없어 실제 노출은 없다.
- 연결하기 전에 저장 시 마스킹하거나, 공개 시 `route_coords`를 빼는 규칙이 필요하다.

### 중 3. 서버 실패 시에도 "공유 완료(200m 보호 적용)" 안내 → 담당자 공유
- `communityApi.shareCommunityCourse`는 요청이 실패해도 `success: true`를 돌려준다. 실제로는 공유되지 않았는데 완료 메시지가 뜬다.
- 위치 노출은 아니지만 사용자에게 사실과 다른 안내다.

### 참고 (하)
- 같은 길 왕복·짧은 코스는 마스킹 후 점 1개만 남아 피드 코스로 의미가 없다. 기존 동작을 유지했다.
- 공유 피드의 `distance_m: 1400`, `duration_min: 22`가 고정값이다.
- GPS 기록이 없으면 앱이 서울 좌표 3개를 대신 보낸다(`WalkReportScreen`).

## 4. 문제없음을 확인한 부분
- 공유 API는 마스킹된 좌표(`masked_polyline`)만 Supabase `community_courses`에 저장하고 피드로 보여 준다. 원본 좌표는 저장·응답하지 않는다.
- 앱의 대체 서버는 `127.0.0.1`(기기 자신)이라, 원본 GPS가 다른 서버로 가지 않는다.
- 산책 기록(GPS 궤적)은 현재 서버로 올라가지 않는다.
