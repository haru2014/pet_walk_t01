# Gemini Code Assist 준수 지침 (GEMINI.md)

본 문서는 **PawTrail (AI Native 반려견 맞춤형 안심 노면 산책 에이전트 및 기록·공유 플랫폼)** 개발 프로젝트에서 VSCode의 Gemini Code Assist 확장이 코드를 분석, 제안, 생성 및 리팩토링할 때 반드시 준수해야 하는 엔지니어링 지침입니다. AI 모델은 모든 응답에서 아래 핵심 원칙과 세부 기술 요구사항을 엄격하게 반영해야 합니다.

---

## [핵심 원칙 0] 감정적인 표현 배제 및 작업 태도

1. **[감정 표현 배제]**: Gemini는 코드 구현, 개선 및 결함 처리를 할 때 감정 표현을 절대 하지 않습니다.
2. **[명확한 한국어 제공]**: Gemini는 모든 답변을 명확하고 간결하며 논리적인 한국어로 제공합니다.
3. **[배포 자율성 제한]**: `eas update`, `eas build`, Supabase 프로덕션 DDL 배포, n8n 프로덕션 웹훅 트리거 등 클라우드 배포/빌드/인프라 명령어는 **사용자의 명시적 요청이나 사전 승인 없이 임의로 자동 실행하지 않으며**, 필요한 경우 명령어 텍스트 및 가이드만 안내합니다.
4. **[검증 신뢰성]**: 가짜 lint/빌드/테스트 수행 결과를 제공하지 않으며 실제 실행 결과만을 기반으로 보고합니다.
5. **[신규 기능 및 변경사항 전수 테스트 의무]**: 기획 및 사용자 스토리에 명시되지 않은 신규 기능, 비즈니스 로직, UI 컴포넌트, 유틸, 서비스가 추가되거나 기존 코드가 수정될 경우, 기존 시스템과의 상호작용 및 회귀 결함(Regression)을 사전에 차단하기 위해 **전체 테스트 스위트(`python -m pytest test_case/ -v`)를 반드시 자동 실행하여 100% 무결성을 검증**하고 결과를 보고합니다.
6. **[요청하지 않은 기능 추가 절대 금지 (YAGNI & No Spec Creep) 및 예외 처리]**:
   - Gemini는 사용자의 명시적인 요청이나 기획서(`docs/01_PawTrail_Project_Proposal.md`), 애자일 사용자 스토리(`docs/03_PawTrail_Agile_User_Stories.md`, 18개 스토리 / 77pt / 372h), 작업 분할 명세서(`docs/06_PawTrail_Task_Breakdown_and_Estimations.md`, 68개 Task)에 정의되지 않은 부가 기능, 임의의 더미 UI/컴포넌트, 미확정 기능을 자의적으로 추가하거나 임의로 생성하지 않습니다.
   - 기능 개선이나 리팩토링 시에도 사용자가 지시한 요구사항 범위 내에서만 최소·최적의 코드를 작성하며, 실제 활용되지 않는 불필요한 레거시 기능이 발견될 경우 임의로 유지하거나 기능을 확장하지 않고 즉시 배제 및 삭제합니다.
   - **[예외 조항 및 사후 정리 의무]**: 문제 해결, 디버깅, 기술 검증 등을 위해 부득이하게 임시 로직, 보조 UI, 디버깅 코드를 추가해야 하는 예외적인 상황에서는 **반드시 사전에 사용자의 명시적 승인을 받아야 하며**, 해당 목적이 달성되어 **필요성이 소진된 직후에는 지체 없이 해당 코드를 완전히 삭제(원복)하여 코드베이스의 100% 무결성을 회복**해야 합니다.
7. **[데이터베이스 및 저장소 무결성 유지 가이드라인 (Local-First & Supabase)]**:
   - **주석 기반 리팩토링 금지**: 로컬 스토리지(`AsyncStorage`) 스키마나 Supabase 데이터베이스 스키마를 변경하는 리팩토링을 수행할 때는 **주석만 수정하거나 백업 주석만 추가하는 행위를 절대 금지**합니다.
   - **자동 업데이트/마이그레이션 스크립트 직접 실행 및 검증**: 모든 데이터 스키마 변경 작업(예: 반려견 프로필 필드 구조 변경, 산책 이력 포맷 변경 등)은 반드시 마이그레이션 스크립트를 작성하여 직접 실행하고 검증해야 합니다.
   - **검증 및 결과 보고**: 스크립트 실행 후에는 변경이 정상적으로 완료되었는지 **실제 데이터 조회를 통해 확인(Verification)**하고, 변경 전후의 데이터 개수 및 구조를 **반드시 보고서에 명시**해야 합니다.
   - **데이터 손실 방지**: 스크립트 실행 전/후의 데이터 정합성을 보장하기 위한 안전장치(JSON 백업 파일 생성 등)를 마련하고, 문제 발생 시 즉시 롤백할 수 있는 절차를 문서화해야 합니다.
8. **[시선 해방(Eyes-Free) 백그라운드 음성 길 안내 구현 가이드라인]**:
   - **구현의 원칙**: 음성 길 안내 구현 시 단순한 텍스트 알림을 넘어, **구조화된 노면 및 회전 데이터 기반의 실시간 음성 브리핑**을 구현해야 합니다.
   - **데이터 연동 및 백그라운드 런타임**:
     - Android Foreground Service(`expo-location`)를 통해 화면이 꺼진 주머니 보관 상태에서도 GPS 위치를 무중단 추적합니다.
     - OSRM `steps` 및 노면/경사 속성을 결합하여 `expo-speech`로 회전 30m 전 알림 및 노면 브리핑("50m 앞 완만한 흙길입니다. 우회전하세요")을 송출합니다.
     - 코스 경로에서 40m 이상 이탈 시 즉시 음성 경고를 제공하고 안전 우회 재탐색(`POST /api/v1/walk/reroute`)을 유도합니다.
9. **[코드 파편화 방지 및 공통 모듈화 원칙 (Rule of Three & SSOT)]**:
   - **공통 모듈화 기준**: 3곳 이상(예: 플래너 화면, 보행 안내 화면, 산책 기록 화면 등)에서 중복되거나 유사하게 사용되는 UI 컴포넌트, 비즈니스 로직, 상태 훅(Custom Hook), 텍스트/데이터 포맷터는 개별 화면에 파편화하여 구현하지 않고, 반드시 **공통 유틸/컴포넌트/훅(`components/`, `hooks/`, `utils/` 또는 `backend/services/`, `backend/utils/`)으로 모듈화하여 호출**합니다.
   - **단일 진실 공급원(SSOT) 준수**: 기능 개선이나 버그 수정 시 단 하나의 공통 모듈만 수정해도 이를 참조하는 모든 화면에 일괄 적용되도록 설계하여 코드 파편화로 인한 정책 불일치를 방지합니다.
   - **100% 하위 호환성 유지**: 공통 모듈화 및 리팩토링 시 기존 import 경로 및 인터페이스와의 호환성을 철저히 보장합니다.

## [핵심 원칙 1] 프로젝트 파일들 사이의 일관성 유지 (Project-Wide Consistency)

Gemini는 새로운 코드를 제안하거나 기존 코드를 수정할 때, 프로젝트에 기정의된 아키텍처와 코딩 컨벤션을 완벽하게 준수해야 합니다.

1. **상태 관리 및 데이터 흐름 일관성**:
   - 클라이언트 상태는 React Hooks(`useState`, `useEffect`, `useMemo`, `useCallback`)를 통해 관리하며, 과도한 전역 상태 생성을 지양합니다.
   - **Local-First 프라이버시 원칙**: 반려견 프로필, 상세 보행 GPS 궤적 등 민감 개인정보는 서버로 전송하지 않고 사용자 기기 내부 `AsyncStorage`에만 보관하며, JSON 로컬 백업/복원 기능을 제공합니다.
   - **Supabase Cloud 역할 한정**: 서버 DB는 공개 커뮤니티 코스(출발지/도착지 200m 공간 마스킹 필수), 현장 위험 제보, 간편 이메일 가입/로그인(Supabase Auth)에만 한정하여 최소한으로 운영합니다.
   - **백엔드 무상태(Stateless) 아키텍처**: FastAPI 백엔드는 세션/DB에 견주 상태를 영구 누적하지 않고, 클라이언트가 전달한 단발성 페이로드(`client_dog_context`, `client_recent_feedback`)를 기반으로 예측 가능한 REST API 처리를 수행합니다.

2. **AI 모델 체인 및 프롬프트 모듈화 구조 준수**:
   - **Gemini 가용 모델 순차 선택 체인 (Cascading Fallback)**: 반드시 `GeminiModelSelector`를 통해 **1순위 `gemini-3.5-flash-lite` ➔ 2순위 `gemini-3.1-flash-lite` ➔ 3순위 `gemini-3.6-flash`** 순으로 자동 선택 호출하며, 구형 `gemini-1.5` 계열 호출은 전면 배제합니다.
   - **Pydantic V2 Strict & Structured JSON**: 모든 API 입출력은 Pydantic V2 스키마를 강제하고, 비전 분석 시 `response_mime_type="application/json"`을 적용하여 환각 없는 구조화된 데이터를 보장합니다.

3. **디자인 시스템 및 스타일링 통일**:
   - 컴포넌트 스타일링 시 `StyleSheet.create`를 사용하며, 공통 디자인 토큰을 엄격히 준수합니다.
   - **노면 및 보행 환경별 표준 색상 규격 (Polyline & Badge)**:
     - 흙/잔디길 (Dirt / Grass): 초록색 (`#10B981`)
     - 흙길 (Dirt / Ground): 갈색 (`#92400E`)
     - 우레탄/탄성포장 (Rubber / Cushion): 주황색 (`#F97316`)
     - 보도블록 (Standard Paved): 파란색 (`#3B82F6`)
     - 아스팔트 (Asphalt - 경고): 짙은 회색 (`#6B7280`)
     - 위험 노면/급경사 (Hazard / Steep): 빨간색 (`#EF4444`)
   - **야외 시인성 및 한 손 조작성**: 태양광 아래 시인성을 위해 저반사 아이보리 배경(`#FAFAFA`)과 고대비 차콜 텍스트(`#1E293B`)를 적용하고, 하단 50% Thumb Zone 및 48px 이상의 안전 터치 영역을 유지합니다.

4. **네이밍 컨벤션 명문화**:
   - 프론트엔드 파일명 및 컴포넌트명: PascalCase (`WalkMapScreen.tsx`, `SafetySummaryCard.tsx`)
   - 프론트엔드 함수, 변수, 훅명: camelCase (`useWalkTracking`, `isTrackingActive`)
   - 백엔드 파일명 및 함수/변수명: snake_case (`generate_loop_route`, `safety_score`)
   - 데이터 모델 및 DB 필드명: 선언된 스키마 규칙에 맞게 정확히 일치시킵니다.

## [핵심 원칙 2] 전체 프로젝트 파일 대상 작업 수행 (Full-Scope Awareness)

Gemini는 단일 파일이나 특정 코드 블록만을 고립적으로 분석해서는 안 되며, 전체 프로젝트의 연관 컨텍스트를 작업 범위로 동기화해야 합니다.

1. **상호 의존성 크로스 체크**:
   - 특정 프론트엔드 화면의 코드를 변경할 때, 이와 연결된 네비게이션 설정, 백그라운드 GPS 리스너, 로컬 스토리지 키 정합성을 함께 검증합니다.
   - 백엔드 Pydantic V2 DTO 스키마 수정 시, 프론트엔드 TypeScript 인터페이스 및 pytest 테스트 픽스처와의 정렬 상태를 동시 동기화합니다.
   - 단일 파일 수정 시 관련된 AI Agent 도구(`@tool`), 라우팅 어댑터, Supabase RLS 보안 규칙에 미치는 영향을 종합적으로 분석하고 필요한 화면을 함께 수정합니다.

2. **환경 설정 파일 동기화**:
   - 패키지 추가나 네이티브 모듈 변경 제안 시, `package.json`, `app.json` (Expo SDK 51+), `eas.json`, `requirements.txt` 간의 호환성을 먼저 검토합니다.
   - 의존성 버전 충돌이 예상되는 경우 무조건적인 최신 버전 제안을 지양하고 현재 프로젝트 종속성 트리에 맞춘 안정적 버전을 제안합니다.
   - 안드로이드 빌드 환경의 특수성(긴 경로 제한 등)을 고려하여 불필요하게 깊은 중첩 폴더 생성을 피합니다.

## [핵심 원칙 3] 모바일(Android/Expo) 플랫폼 안정성 및 핸즈프리 런타임 무결점 유지 (Android Stability & Hands-Free Runtime)

PawTrail 앱은 React Native 및 Expo 기반의 안드로이드 환경을 주요 타깃으로 하므로, 빌드 및 실행 시스템의 안정성을 저해하는 코드를 생성해서는 안 됩니다.

1. **백그라운드 GPS 및 음성 안내(TTS) 안정성**:
   - **포그라운드 서비스 크래시 방지**: `expo-location` 백그라운드 태스크 등록 시 Android 네이티브 노티피케이션 채널 및 Foreground Service 타입을 정확히 설정하여 비정상 종료를 방어합니다.
   - **TTS 음성 큐 무결성**: `expo-speech` 발화 시 이전 발화 인터럽트 처리 및 연속 호출 큐를 체계적으로 관리하여 음성 겹침이나 누락을 방지합니다.
   - **GPS 튐 및 도심 음영 방어**: 도심 빌딩 숲에서 발생하는 GPS 오차를 방어하기 위해 칼만 필터 및 도로망 스냅 보정(Dead Reckoning)을 적용하여 화면 꺼짐 상태에서도 궤적 손실을 차단합니다.

2. **네이티브 빌드 사양 준수**:
   - Android SDK, Gradle 빌드 도구와의 호환성을 보장하는 구조로 안드로이드 설정을 관리합니다.
   - 파일 시스템 접근, 인코딩 파싱 로직 작성 시 **'절대 경로 내 비-ASCII 문자 포함 금지'** 및 **'공백 경로 처리 래핑'** 규격을 반영하여 윈도우/리눅스 환경 빌드 락(Lock)을 방어합니다.

3. **자원 관리 및 런타임 안정성**:
   - 백그라운드 위치 리스너, 센서, 애니메이션 루프 호출 시 컴포넌트 언마운트 시점에 자원이 메모리에서 정상적으로 해제되도록 정리(Cleanup) 함수를 반드시 포함합니다. (메모리 누수 방지)
   - 비동기 처리(`async/await`) 구간 전체에 예외 처리(`try-catch`)를 누락 없이 적용하여 앱 불시 종료(App Crash)를 예방합니다.
   - 최신 OS 대응을 위해 **Android 14+ 포그라운드 서비스 및 위치 권한 요청**을 올바르게 반영합니다.

## [핵심 원칙 4] SonarLint Code Smell 방지 (Clean Code Compliance)

프로젝트 정적 분석 도구(SonarLint) 기준 및 클린 코드 원칙을 완벽하게 준수하여 기술 부채를 사전에 차단합니다.

1. **구조 및 복잡도 최적화**:
   - **[S3776] 인지 복잡도 제한**: 함수당 인지 복잡도는 10 이하를 유지하며, 복잡한 조건문/반복문은 독립된 헬퍼 함수나 커스텀 훅으로 분리합니다.
   - **[S2004] 콜백 중첩 방지**: 익명 함수 및 콜백이 4단계 이상 깊게 중첩되지 않도록 독립된 기명 함수로 추출합니다.
   - **[S3358] 중첩 삼항 연산자 금지**: 가독성을 해치는 중첩 삼항 연산자는 절대 금지하며 독립적인 렌더링 헬퍼 함수와 `if-else` 또는 매핑 객체(`Record<Key, Value>`)로 명확하게 처리합니다.
   - **[코드 규모 임계치]**: 단일 파일 250라인 이하, 단일 함수 40라인 이하를 엄격히 유지합니다.

2. **최신 표준(ES6+ / Python 3.11) 및 리팩토링 패턴 사용**:
   - **[S6582] 옵셔널 체이닝 및 안전한 널 처리**: 객체 탐색 시 옵셔널 체이닝(`?.`)과 널 병합 연산자(`??`)를 사용하여 런타임 예외를 원천 방어합니다.
   - **[S1128 / S1481] 데드 코드 및 미사용 Import 즉각 제거**: 미사용 변수, 미사용 import, 불필요한 콘솔 로그, 임시 주석은 파일 저장 전 100% 정리합니다.
   - 방어 코드는 논리 연산 최좌측에 우선 배치하여 단락 평가(Short-circuit) 효율을 극대화합니다.
   - 배열 순회 시 고유 ID를 `key`로 사용하며 단순 인덱스 사용을 지양합니다.

## [핵심 원칙 5] 코드 리팩토링, 불필요한 코드 제거 및 간소화 (Refactoring & Code Simplification)

코드베이스의 유지보수성과 생산성을 위해 리팩토링, 데드 코드 제거, 코드 간소화를 상시 수행합니다.

1. **단일 책임 원칙(SRP) 기반 모듈화 및 슬림화**:
   - 250줄 이상의 비대해진 모놀리식 파일은 역할(데이터, 도메인 헬퍼, 비즈니스 서비스, UI 컴포넌트)에 따라 적극적으로 분리합니다.
   - 모듈 분리 시 기존 import 경로와의 호환성을 위해 진입점(Entry Point)에서 **100% 하위 호환 re-export**를 반드시 유지합니다.

2. **불필요한 코드(Dead Code / Legacy Code) 및 미요청 기능 원천 제거 (DRY & YAGNI 원칙)**:
   - 미사용 변수, 미사용 import, 더미 함수, 주석 처리된 레거시 코드는 남겨두지 않고 즉시 삭제합니다.
   - 기획서 및 18개 사용자 스토리 외에 과거 관행이나 임의로 삽입된 미활용 더미 기능은 보존하지 않고 원천 제거합니다.
   - 여러 컴포넌트나 서비스에 걸쳐 중복 선언된 로직과 상수는 공통 모듈로 통합하여 단일 진실 공급원(SSOT)을 유지합니다.

3. **코드 간소화 및 가독성 극대화 (Code Simplification)**:
   - **조기 반환(Early Return / Guard Clauses)**: 복잡한 중첩 `if-else` 대신 유효성 검사 실패 또는 예외 케이스를 함수 최상단에서 즉시 반환하여 들여쓰기 뎁스를 최소화합니다.
   - **불필요한 상태(State) 생성 지양**: 기존 props나 상태로부터 유도 가능한 계산값은 별도의 `useState`를 만들지 않고 순수 변수 연산이나 `useMemo`로 단순화합니다.
   - **가독성 좋은 주석 제공**: 유지보수성 향상을 위해 명확한 한글 주석을 제공하되, 코드와 불일치하거나 불필요한 주석은 정리합니다.

## [핵심 원칙 6] UX 요건 및 긍정적 웰니스 카피라이팅 가이드라인 (UX Consistency & Rules)

사용자 인터페이스(UI)나 사용자 경험(UX)에 영향을 미치는 코드를 개발/수정할 때, Gemini는 반드시 사전에 정의된 UX 규칙과 가이드를 준수해야 합니다.

1. **UX 기본 원칙 준수 (`.gemini/UX_COMPACT_RULES.md`)**:
   - 명확한 1차 목적(Clarity), 시각적 위계(Hierarchy), 야외 시인성(Readability in Sunlight), 안전한 터치 타깃(Touch Target >= 48px), 하단 50% Thumb Zone 배치를 준수합니다.
   - 불필요하게 복잡한 UI 요소를 배제하고 반응형 레이아웃과 접근성 요건을 코드 레벨에 적용합니다.

2. **UX 자가 점검 및 리뷰 (`.gemini/UX_REVIEW_PROMPT.md`)**:
   - UI/UX 관련 코드 작성 완료 시 자가 점검 체크리스트를 기반으로 검증합니다.
   - 지도 로딩(Skeleton/Spinner), 경로 탐색 실패, 위치/카메라 권한 거부, 네트워크 단절 등 예외 상태(Empty, Loading, Error)가 완벽히 처리되었는지 확인합니다.

3. **[앱 전역 긍정적 웰니스 카피라이팅 100% 준수 (Zero Medical Slang)]**:
   - 앱 화면 UI, 온보딩, TTS 음성 안내 스크립트, AI 프롬프트 전역에서 '슬개골 탈구', '관절염', '수술', '질환 단계' 등 임상적/의학적 공포 유발 단어 노출을 엄격히 금지합니다.
   - 발견 즉시 **"폭신한 길"**, **"관절 안심 케어"**, **"부드러운 잔디/흙길"**, **"편안한 발걸음"**으로 순화 통일합니다. (※ 의학 통계 및 질환 메커니즘은 투자 유치/심사용 발표 자료에만 제한적으로 유지)
   - 서비스 내 상시 AI 면책 고지 문구를 필수로 유지합니다:
     > *"본 서비스의 AI 분석 및 추천은 안전한 산책을 돕기 위한 참고 정보이며 수의학적 진단이 아닙니다. 실제 보행 시 현장 상황에 유의하시기 바랍니다."*
