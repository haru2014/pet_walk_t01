# 편안하개 프로젝트 발표 디자인 시스템 (초안)

## 적용 범위
이 기준은 편안하개 프로젝트의 협업, 앱 구현, 품질 검증과 결과를 설명하는 발표에 적용합니다. Sorbet 파스텔 스타일을 사용합니다. 4:3 비율은 앞서 정한 요구사항대로 유지합니다. 주제·목적·청중·내용 범위는 발표별로 확인하며, 현재 발표 주제는 편안하개 프로젝트입니다.

## 슬라이드 규격
- 기본 화면 비율: 4:3
- 모든 슬라이드 배경: #FBF7FB
- 기본 정렬: 왼쪽 정렬. 중앙 정렬은 표지나 시각 중심이 필요한 경우만 사용
- 여백을 넉넉히 두고 슬라이드마다 핵심 메시지 하나를 중심으로 구성
- 콘텐츠 패널: 흰색 #FFFFFF, 1px 라일락 테두리 #ECE3F0, 모서리 반경 24–32px
- 패널, 배지, 단계 표시 등 모서리를 둥글게 처리. 딱딱한 직사각형 패널은 사용하지 않음
- 그림자는 사용하지 않음

## 색상

### 바탕과 텍스트
| 역할 | HEX | 적용 |
|---|---|---|
| 슬라이드 배경 | #FBF7FB | 모든 슬라이드 |
| 패널 | #FFFFFF | 콘텐츠 영역 |
| 패널 테두리 | #ECE3F0 | 1px 경계선 |
| 제목 | #4A3A5C | 제목과 핵심 문구 |
| 본문 | #6A5E76 | 설명 |
| 작은 레이블·캡션 | #A99FB3 | 보조 정보 |

### 파스텔 강조색
1. 라일락 #9B6FBF
2. 피치 핑크 #F2A6B3
3. 민트 #8FD0C4
4. 버터 #F4D58D

- 이 순서로 색 블록을 반복합니다.
- 라일락을 주 강조색으로 쓰고 나머지 색을 균형 있게 돌려 씁니다.
- 넓은 면은 흰색에 가까운 옅은 색조로, 원색은 작은 점·연결선·짧은 강조에만 사용합니다.
- 슬라이드당 강조색은 이 네 색으로 제한합니다. 지정된 배경·텍스트 색상은 역할에 따라 별도로 사용합니다.
- 강조색이 넓은 면적 전체를 차지하지 않게 합니다.

## 장식과 그래픽
- 대표 모티프는 둥근 블롭입니다. 둥근 도형이나 인라인 SVG 경로를 사용할 수 있습니다.
- 배경 블롭에만 라일락 #9B6FBF에서 피치 핑크 #F2A6B3로 흐르는 저채도 그라데이션을 허용합니다.
- 블롭은 콘텐츠 뒤에 놓고 낮은 불투명도나 흐림을 사용해 은은하게 표현합니다. 글자와 차트의 가독성을 가리면 제거합니다.
- 패널과 단계 표시는 둥근 모양을 사용합니다.
- 스톡 사진, 클립아트, 이모지, 그림자, 네온색, 충돌하는 색, 각진 카드, 거친 테두리는 사용하지 않습니다.

## 글꼴과 위계
- 제목 H1–H6: Baloo 2, 30–64px
- 본문·레이블·숫자: Quicksand
- 제목은 #4A3A5C, 본문은 #6A5E76, 작은 레이블과 캡션은 #A99FB3
- 숫자와 통계는 크게 표시하고 파스텔 알약형이나 둥근 블롭에 배치할 수 있습니다.
- 밀집한 글머리표 목록을 피하고, 핵심 내용을 짧은 문장과 시각 구조로 나눕니다.
- px 기준은 시각 크기 요구입니다. PPTX 도구의 pt 단위 변환과 한글 글리프 지원은 시제품에서 확인합니다.
- 글꼴 대체가 필요하면 확인 없이 바꾸지 않고 사용자에게 알립니다.

## 레이아웃 패턴

### 표지
- 옅은 라일락 배경과 넉넉한 여백 사용
- 프로젝트명과 발표 제목을 Baloo 2로 강조
- 한 줄 목적 설명을 Quicksand로 배치
- 공식 로고가 제공되면 원형을 유지. 없으면 편안하개 텍스트로 표기하고 로고를 지어내지 않음
- 옅은 라일락-피치 블롭을 배경에 배치할 수 있음

### 본문과 협업 과정
- 흰색 둥근 패널과 옅은 라일락 테두리 사용
- 역할, 일정, 구현 흐름은 둥근 단계 표시와 파스텔 연결선으로 표현 가능
- 팀원의 이름과 기여는 저장소 자료로 확인되는 내용만 사용
- 한 장에 많은 내용을 넣지 않고 필요하면 슬라이드를 나눔

### 수치와 검증 결과
- 편집 가능한 표·차트를 우선
- 네 가지 파스텔 색 안에서 일관되게 구분
- 수치에 기준일, 표본, 측정 조건과 근거를 표시
- 미확인 수치와 다른 시점의 수치를 합쳐 하나의 성과로 표현하지 않음

### 제품 화면
- 실제 앱 캡처는 구현 상태와 버전을 확인
- 목업을 실제 구현 화면처럼 표시하지 않음
- 캡처에 포함된 민감정보를 제거하거나 비식별화

## 검토 기준
- 색상만으로 상태를 표현하지 않고 텍스트나 모양을 함께 사용
- 작은 캡션을 핵심 정보에 쓰지 않음
- 4:3 화면에서 글자, 표, 차트가 읽히는지 전체 슬라이드를 렌더링해 확인
- 글자 잘림, 겹침, 패널 간격, 대비, 폰트 대체를 확인
- 내용과 수치를 근거 문서와 대조하고 미확인 주장을 성과로 표현하지 않음

## 발표별 적용 순서
1. 주제·목적·청중·범위·근거자료·분량을 확인합니다. 이미 제공된 항목은 다시 묻지 않습니다.
2. presentation/references/source-log.md에서 자료 후보를 찾고 원문을 확인합니다.
3. 4:3 비율과 이 디자인 시스템을 적용해 슬라이드 구성안을 작성합니다.
4. PPTX를 생성하고 모든 슬라이드를 렌더링해 검토합니다.
5. 오류를 수정하고 편집 가능한 최종 파일을 전달합니다.
