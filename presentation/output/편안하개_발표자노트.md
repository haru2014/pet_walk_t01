## 슬라이드별 발표 노트

### 1. 편안하개

“코디세이 네이티브 과정에서 학습한 AI·데이터·앱 개발을 하나의 사용자 경험으로 연결한 결과를 말씀드리겠습니다. 오늘은 앱 기능 소개뿐 아니라 팀이 어떻게 나누어 만들고, 무엇으로 검증했으며, 어떤 검증이 아직 남았는지 함께 설명하겠습니다.”

### 2. 문제 정의

“문제 정의서와 README가 겨냥하는 과제는 세 가지입니다. 산책 전에 계단이나 경사 같은 길 조건을 알기 어렵고, 걷는 중 화면을 보게 되며, 반려견마다 다른 체급과 케어 조건을 반영하기 어렵다는 점입니다. 이 세 가지는 프로젝트의 문제 가설입니다. 별도의 사용자 조사 결과나 인터뷰 통계로 검증됐다고 말하지 않겠습니다.”

### 3. 제품 경험

“사용자가 산책 시간과 선호를 입력하고, 에이전트가 코스를 추천합니다. 실제 걷는 동안에는 GPS와 음성 안내를 사용하고, 끝난 뒤 활동 기록을 남기거나 코스를 선택해 공유합니다. 기능을 독립된 화면으로 끝내지 않고 전후 흐름을 이어 주는 것이 제품 설계의 중심입니다.”

### 4. AI 설계

“AI의 역할은 일반적인 안내 문장을 만드는 데 그치지 않습니다. LangGraph 기반 산책 계획 에이전트가 사용자의 요청과 로컬 프로필을 바탕으로 경로 도구와 보행망 분석을 연결하고 후보를 평가합니다. FastAPI가 모바일 앱과 이 경로 계산을 연결합니다. 보고서와 코드에서 확인되는 구조를 요약한 것이며, 모든 추천이 실제 현장에서 최적이라는 주장과는 구분합니다.”

### 5. 경로 품질

“README에는 대전 3개, 세종 2개 공원으로 총 5개 파일럿 거점이 기록되어 있습니다. 보행망의 계단 태그, DEM 경사 분석, 기상청 예보와 지면열 추정이 코스 계산에 쓰입니다. 여기서 강조할 것은 모델 하나에 의존하지 않고 실제 보행망과 환경 데이터를 함께 사용하도록 구성했다는 점입니다.”

### 6. 개인정보 설계

“반려견 프로필과 원본 산책 궤적 같은 민감 정보는 기기 로컬에 보관하고, 사용자가 공유를 선택한 코스 데이터는 커뮤니티 API로 전달하는 구조를 문서와 코드에서 확인할 수 있습니다. 공유 시 출발·도착 주변 200m를 마스킹하는 원칙도 반영했습니다. 이는 설계와 테스트 근거이며 개인정보 노출이 어떤 상황에서도 불가능하다고 단정하지는 않습니다.”

### 7. 앱 화면

“이 화면은 저장소의 실제 앱 캡처 갤러리에 포함된 2026년 10월 18일 화면입니다. 홈에서 산책 준비와 지수를 확인하고, 마이 탭에서 활동 기록을 보며, 커뮤니티 피드에서 이웃 코스를 확인할 수 있습니다. 가운데 화면은 활동 기록 UI이고, 오른쪽은 커뮤니티 피드입니다. 캡처는 기능 화면의 근거이지 모든 기기에서의 현재 운영 상태를 보증하지는 않습니다.”

### 8. 팀 협업

“팀 빌딩 문서의 R&R에 따라 조현정은 PM과 AI 에이전트, 전황진은 공간 데이터, 노희선은 서버와 경로 계산, 김승현은 모바일과 GPS/음성 안내, 김정님은 UI/UX와 품질 검증을 맡았습니다. 이 역할 분담의 의미는 전문 영역을 나누면서도 API, 산책 시나리오, 테스트 지점에서 다시 연결했다는 점입니다. 개인별 기여도 평가는 이 문서의 역할 범위를 넘어서 주장하지 않습니다.”

### 9. 품질 근거

“현재 루트 README에는 백엔드 테스트 796개 통과, 5개 건너뜀, 프론트엔드 406개 통과, TypeScript 오류 0건이 기록되어 있습니다. 이는 저장소 문서에 적힌 결과로, 이번 발표를 만들면서 테스트를 다시 실행한 수치는 아닙니다. 평가 시에는 재현 가능한 CI 로그와 함께 확인할 수 있도록 하겠습니다.”

### 10. 성능 측정

“10월 21일 성능 보고서는 FastAPI TestClient와 로컬 Fast-Path 캐시·라우팅 어댑터 환경에서 측정했습니다. 공원 경로 생성 warm P95는 112.55ms, 주차장 P&R은 91.54ms입니다. 반면 기상 위험 조회의 첫 호출은 3,356ms였고 같은 표에서 1.5초 SLA 미달로 기록했습니다. 경로 생성의 warm 결과를 모든 API나 첫 호출 성능으로 일반화하지 않고, 이 기상 첫 호출은 개선 과제로 인정합니다.”

### 11. 배포와 실사용 검증

“루트 README에는 테스트용 APK와 운영 서버 주소가 안내되어 있습니다. 10월 21일 Code Freeze 감사 문서에는 5개 거점 E2E 사전 시뮬레이션 통과가 기록되어 있습니다. 다만 5인 현장 CBT는 10월 31일부터 11월 7일까지 예정된 일정입니다. 따라서 실제 반려견 보호자 피드백과 반영 결과는 이 발표 시점의 완료 성과로 계산하지 않습니다. 최종 미션의 실사용자 검증까지 닫기 위해 다음 단계로 수행할 계획입니다.”

### 12. 질의응답

“정리하면 세 가지입니다. AI를 제품 흐름에 연결했고, 산책 안전과 프라이버시를 설계에 반영했으며, 자동화 검증 결과와 남은 현장 검증을 구분했습니다. 이제 질의응답을 진행하겠습니다.”

## 예상 질의와 답변 근거

### 실제 사용자 피드백을 받아 제품을 개선했습니까?

현재 확인한 문서에는 5인 CBT 시나리오와 10월 31일~11월 7일 실행 계획이 있습니다. 10월 23일 기준 완료된 실제 현장 테스트·피드백 보고서는 확인하지 못했습니다. 발표에서는 “사전 시뮬레이션 완료, 현장 CBT 예정”이라고 답합니다.

### 백엔드 테스트는 전부 통과했습니까?

README에는 801개 수집, 796개 통과, 5개 skip이라고 적혀 있습니다. 따라서 “전체 통과” 대신 “796 통과, 5 skip”이라고 정확히 답합니다. 이 자료 작업 중 테스트를 다시 실행하지 않았습니다.

### 성능 목표를 만족합니까?

공원 경로와 P&R의 warm P95는 각각 112.55ms와 91.54ms로 보고됐습니다. 기상 위험 조회 첫 호출은 3,356ms이고 표에서 SLA 미달입니다. 어떤 API를 말하는지와 warm/cold 조건을 나눠 답합니다.

### 개인정보는 서버에 저장되지 않습니까?

문서와 구현 구조상 프로필·원본 궤적은 로컬 우선이고, 선택 공유 코스 및 현장 제보는 서버와 연동됩니다. 공유 코스에는 200m 마스킹이 적용됩니다. “서버 저장이 전혀 없다”라고 답하지 않습니다.

### 운영 서버가 실제로 배포되어 있습니까?

루트 README에 테스트 APK 다운로드 링크와 운영 서버 주소가 기재되어 있습니다. 이 발표 준비에서는 주소에 접속해 현재 가용성을 확인하지 않았으므로 “README에 배포 주소가 공개되어 있다”고 답합니다.
