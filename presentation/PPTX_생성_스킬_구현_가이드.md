# Codex PPTX 생성 스킬 구현 안내서

이 문서는 첨부된 네이버 블로그 PDF의 제작 흐름을 Codex와 이 저장소에 맞춰 옮기는 방법을 설명합니다. 코드를 처음 다루는 사람도 순서대로 진행할 수 있도록, 각 단계의 목적과 만들 파일, 확인 방법을 함께 적었습니다.

## 먼저 알아둘 점

블로그 글의 중심 흐름은 다음 세 단계입니다.

1. 브랜드의 색상, 글꼴, 레이아웃을 정리해 재사용할 디자인 기준을 만듭니다.
2. 그 기준으로 실제 PowerPoint 파일을 만들고, 내용을 수정할 수 있는지 확인합니다.
3. 반복할 작업 절차를 `SKILL.md`에 저장해 다음 요청에서 다시 사용합니다.

블로그의 예시는 Claude Code와 Claude의 스킬 저장 방식에 맞춰져 있습니다. 이 문서는 같은 아이디어를 Codex 저장소에 적용합니다. 현재 Codex 저장소 단위 스킬 경로는 `.agents/skills/<스킬이름>/SKILL.md`입니다. Gemini CLI도 이 공용 경로를 인식하므로, 두 도구에서 같이 쓰려면 스킬 지침은 `.agents/skills/`에 두고 PPT 디자인 자료는 루트의 `presentation/`에 모읍니다. `presentation/` 안에만 `SKILL.md`를 두면 자동으로 발견된다고 가정하지 마세요.

## 완성할 폴더 구조

처음부터 모든 폴더를 만들 필요는 없습니다. 아래 구조를 목표로 두고 단계별로 필요한 폴더만 추가합니다.

```text
저장소 루트/
├─ .agents/
│  └─ skills/
│     └─ pptx-maker/
│        ├─ SKILL.md             # Codex가 읽는 스킬 안내서
│        ├─ references/          # 세부 지침과 예시
│        └─ scripts/             # 반복 작업을 자동화할 때만 추가
└─ presentation/
   ├─ README.md                  # 이 자료 폴더의 사용법
   ├─ design-system.md           # 색상, 글꼴, 여백, 레이아웃 규칙
   ├─ references/                # 참고 자료의 출처와 사용 메모
   ├─ templates/                 # 검토된 PPTX 템플릿이나 레이아웃 자산
   ├─ examples/                  # 작은 검증용 입력과 결과 예시
   ├─ output/                    # 사용자가 요청한 최종 PPTX
   └─ evals/                     # 스킬 동작 확인용 요청과 체크 기준
```

실제 파일 생성 스크립트가 필요해지면 `scripts/`를 스킬 폴더에 추가합니다. 처음부터 자동화 코드를 많이 만들기보다, 먼저 사람이 확인할 수 있는 작은 결과물을 만드는 편이 문제를 찾기 쉽습니다.

## 단계 1. 저장소와 목표 확인하기

### 할 일

1. 저장소 루트에서 현재 파일과 기존 규칙을 확인합니다.
2. `presentation/` 폴더가 이미 있는지 확인합니다. 있으면 기존 파일을 읽고 이어서 사용합니다.
3. 스킬이 만들 PPT의 사용 목적을 한 문장으로 정합니다. 예: “보고서 자료를 받아 편집 가능한 10장 안팎의 PowerPoint로 정리한다.”
4. 결과 파일의 기본 형식을 `.pptx`로 정합니다.

### 초보자용 요청 예시

```text
이 저장소에서 PPT 관련 파일과 기존 작성 규칙을 먼저 확인해 줘.
새 파일을 덮어쓰지 말고, 현재 폴더 구조와 충돌 가능성을 짧게 알려 줘.
```

### 완료 확인

- 저장소에서 PPT 관련 기존 작업물을 확인했습니다.
- PPT의 주 사용자와 용도를 정했습니다.
- 기존 파일을 덮어쓰지 않을 위치를 정했습니다.

## 단계 2. 디자인 자료 모으기

블로그 글은 브랜드 디자인 가이드와 완성된 슬라이드 사례를 출발점으로 삼습니다. 예를 들면 `DESIGN.md`처럼 브랜드의 디자인 규칙이 적힌 문서와, 참고할 만한 슬라이드 예시를 함께 살펴봅니다.

### 할 일

1. 로고, 브랜드 가이드, 기존 PPT, 색상 코드, 글꼴 정보를 모읍니다.
2. 외부 웹사이트에서 가져온 이미지·폰트·템플릿은 출처와 사용 조건을 기록합니다.
3. 참고 자료가 없으면 사용자가 원하는 분위기와 색상 방향을 먼저 정하고, 임의로 특정 브랜드를 복제하지 않습니다.
4. `presentation/references/`에 자료별 출처와 사용할 범위를 간단히 기록합니다.

### 자료 메모 예시

```text
자료명: 회사 브랜드 가이드.pdf
출처: 사내 공유 자료
확인한 내용: 로고 비율, 기본 색상, 지정 글꼴
PPT 사용 범위: 색상과 글꼴 규칙 참고
```

### 완료 확인

- 사용 가능한 자료와 출처가 정리되어 있습니다.
- 사용할 수 있는지 모르는 이미지나 글꼴은 사용 후보에서 보류했습니다.

## 단계 3. 디자인 시스템 작성하기

`presentation/design-system.md`에 PPT 전체에서 반복 적용할 규칙을 씁니다. 디자인 시스템은 매번 새로 설명하지 않도록 만드는 기준 문서입니다.

### 먼저 정할 항목

- 화면 비율: 기본은 16:9로 시작하고, 기존 템플릿이 있으면 그 비율을 따릅니다.
- 색상: 배경, 본문 글자, 강조, 보조 색상과 각 색의 용도를 기록합니다.
- 글꼴: 제목과 본문 글꼴, 대체 글꼴, 글꼴을 사용할 수 없는 경우의 처리 방법을 기록합니다.
- 글자 크기: 제목, 본문, 각주에 쓸 기준 크기를 정합니다.
- 레이아웃: 표지, 목차, 본문, 데이터 비교, 결론 페이지의 기본 배치를 정합니다.
- 차트와 표: 편집 가능한 PowerPoint 차트·표를 우선할지 정합니다.
- 금지 사항: 글자 잘림, 과도한 장식, 출처 없는 수치·이미지 사용 등을 명시합니다.

### 초안 템플릿

```markdown
# PPT 디자인 시스템

## 용도와 대상
- 주 용도:
- 주 독자:

## 슬라이드
- 화면 비율:
- 바깥 여백:
- 한 슬라이드의 주요 메시지 수:

## 색상
- 배경:
- 본문:
- 강조:
- 보조:

## 글꼴
- 제목:
- 본문:
- 대체 글꼴:

## 구성 규칙
- 표지:
- 본문:
- 표와 차트:
- 출처 표기:

## 검토 규칙
- 글자 잘림 여부 확인
- 데이터와 단위 확인
- 편집 가능한 요소인지 확인
```

처음에는 작은 디자인 기준으로 시작합니다. 한 번에 많은 색상, 레이아웃, 예외 규칙을 정하면 실제 슬라이드에서 무엇이 문제인지 찾기 어려워집니다.

## 단계 4. 도구를 정하고 2~3장짜리 시제품 만들기

블로그 글은 먼저 실제 PPT를 만들어 디자인 기준이 잘 적용되는지 확인한 뒤, 본문 제작으로 넘어갑니다. 같은 순서를 따르되 처음에는 2~3장만 만듭니다.

### 할 일

1. 저장소와 Codex 실행 환경에서 사용할 수 있는 PPTX 제작 도구와 의존성을 확인합니다.
2. 도구 선택을 기록합니다. 도구가 바뀌면 출력 결과나 편집 가능성이 달라질 수 있습니다.
3. 표지 1장, 텍스트 중심 본문 1장, 표나 차트가 있는 본문 1장을 만듭니다.
4. 결과를 PowerPoint 또는 호환 프로그램에서 열어 배치와 글꼴을 확인합니다.
5. 제목, 본문, 표, 차트를 직접 수정할 수 있는지 확인합니다.

### 도구 선택 시 확인할 점

- `.pptx` 파일을 실제로 내보낼 수 있는가?
- 텍스트와 도형이 이미지 한 장으로 합쳐지지 않고 편집 가능한가?
- 표와 차트의 데이터를 나중에 수정할 수 있는가?
- 필요한 런타임과 패키지를 이 저장소에서 사용할 수 있는가?
- 슬라이드를 이미지로 렌더링해 눈으로 검토할 수 있는가?

특정 라이브러리를 미리 정하지 마세요. 이 저장소에서 설치·실행이 가능한지, 그리고 편집 가능한 결과를 만드는지 시제품으로 확인한 다음 결정합니다.

### 완료 확인

- PPTX가 열립니다.
- 주요 글자와 도형이 잘리지 않습니다.
- 한글 글꼴 대체가 발생해도 레이아웃이 무너지지 않습니다.
- 텍스트와 필요한 표·차트를 편집할 수 있습니다.
- 디자인 시스템의 색상과 여백 규칙이 실제로 적용됩니다.

## 단계 5. 대표 자료로 실제 슬라이드 만들기

시제품이 괜찮으면 실제로 자주 만들 PPT 한 종류를 골라 제작합니다. 블로그 글은 자료를 요약·정리해 보고서형 PPT를 만드는 예시를 듭니다.

### 자료 준비

- 입력 자료 파일 또는 사용할 텍스트
- 원하는 슬라이드 수나 발표 시간
- 대상 독자
- 반드시 포함할 내용
- 출처 표기 방식

### 제작 요청 예시

```text
presentation/design-system.md의 규칙을 적용해 PPTX 초안을 만들어 줘.
입력 자료의 사실과 수치는 그대로 유지하고, 출처가 없는 정보는 추가하지 마.
표와 차트는 나중에 값을 수정할 수 있는 형식으로 만들고,
완성 파일은 presentation/output/ 아래에 저장해 줘.
먼저 슬라이드 구성안을 보여 준 뒤 제작을 진행해.
```

자료를 받기 전에는 슬라이드 내용을 지어내지 않습니다. 핵심 주장을 지원하는 근거가 부족하면 빈칸을 임의로 채우지 말고 확인 대상으로 남깁니다.

## 단계 6. 결과 검토와 수정 규칙 정하기

PPTX 파일이 만들어졌다는 사실만으로 완성된 것은 아닙니다. 슬라이드 이미지를 렌더링해 눈으로 확인하고, PPTX를 직접 열어 편집 가능성을 확인합니다.

### 확인 목록

- 요청한 슬라이드 수와 목차가 맞습니까?
- 각 슬라이드의 제목이 실제 내용을 설명합니까?
- 글자가 잘리거나 겹치거나 너무 작지 않습니까?
- 색상 대비와 글꼴이 디자인 시스템과 일치합니까?
- 표·차트의 값, 단위, 범례가 입력 자료와 일치합니까?
- 외부 자료의 출처가 빠지지 않았습니까?
- 표, 차트, 텍스트를 수정할 수 있습니까?
- 최종 파일이 `presentation/output/`에 있고, 임시 이미지나 중간 산출물이 최종본과 혼동되지 않습니까?

문제가 발견되면 어떤 슬라이드의 무엇이 잘못됐는지 적고 수정합니다. 자동 검사가 통과해도 화면을 직접 확인하는 단계를 생략하지 않습니다.

## 단계 7. 반복 절차를 Codex 스킬로 저장하기

시제품과 실제 자료 제작을 한 번 이상 마친 뒤, 반복해서 사용할 절차를 `.agents/skills/pptx-maker/SKILL.md`에 작성합니다. 블로그 글에서도 스킬은 이름, 설명, 작업 지침을 저장해 다음 요청에서 불러오는 역할로 설명합니다.

### 스킬 파일의 기본 형식

```markdown
---
name: pptx-maker
description: 저장소의 디자인 시스템을 적용해 편집 가능한 PowerPoint 프레젠테이션을 작성하고 검토합니다.
---

# PPTX 생성 절차

1. 사용 목적, 독자, 입력 자료, 분량, 출력 위치를 확인합니다.
2. `presentation/design-system.md`를 읽습니다.
3. 입력 자료에 없는 사실이나 수치를 만들지 않습니다.
4. 슬라이드 구성안을 작성한 뒤 PPTX를 만듭니다.
5. 결과를 렌더링해 글자 잘림, 겹침, 출처, 편집 가능성을 확인합니다.
6. 수정 가능한 문제가 있으면 고친 뒤 최종 PPTX 경로를 보고합니다.
```

설명(description)은 스킬이 필요한 요청을 Codex가 알아볼 수 있게 구체적으로 씁니다. `presentation/design-system.md`처럼 스킬 폴더 바깥의 자료를 참조할 때는 저장소 루트 기준 경로를 분명히 적습니다.

처음에는 지침만으로 시작합니다. 매번 같은 수작업이 반복되고 명확한 입력·출력이 확인된 뒤에만 `scripts/`를 추가합니다. 자동화 스크립트는 잘못된 출력을 더 빠르게 만들 수도 있으므로, 예외 처리와 검증 절차도 함께 기록합니다.

## 단계 8. 실제 요청으로 스킬을 시험하기

스킬을 저장한 뒤에는 스킬 이름을 명시해 실행해 보고, 실제 요청에서 원하는 때에 자동으로 선택되는지도 확인합니다. OpenAI의 Codex 안내는 성공 기준을 먼저 정하고, 스킬이 실행됐는지와 결과 규칙을 지켰는지를 작은 평가 사례로 확인하는 방법을 설명합니다.

### 최소 시험 사례

| 사례 | 요청 | 확인할 결과 |
|---|---|---|
| 직접 호출 | “pptx-maker 스킬로 이 보고서를 5장 PPTX로 만들어 줘” | 스킬 지침을 읽고, 지정된 출력 위치에 파일을 만듦 |
| 자연어 호출 | “이 자료를 발표용 PPT로 정리해 줘” | 의도에 맞게 스킬을 선택하고 필요한 정보를 확인함 |
| 자료 부족 | “매출 전망 PPT를 만들어 줘” | 자료에 없는 수치를 임의로 만들지 않고 필요한 입력을 요청함 |
| 편집 가능성 | 표와 차트가 든 자료를 제공 | 필요한 표·차트의 값을 수정할 수 있음 |
| 레이아웃 검토 | 긴 제목이나 많은 내용이 있는 자료 제공 | 글자 잘림·겹침을 확인하고 수정함 |

처음에는 위와 같이 5개 정도의 사례를 사람이 직접 실행하고 결과를 기록합니다. 실패한 요청은 지침이나 검토 목록을 고친 뒤 같은 사례로 다시 확인합니다. 결과가 안정된 후에 평가 자동화를 검토합니다.

### 완료 기준

- 스킬이 직접 호출됩니다.
- 일반 PPT 요청에서도 의도한 경우 스킬이 선택됩니다.
- 근거 없는 정보가 추가되지 않습니다.
- PPTX를 열고 편집할 수 있습니다.
- 렌더링 결과에서 글자 잘림과 겹침이 검토됩니다.
- 최종 PPTX가 정해진 위치에 저장됩니다.

## 초보자용 진행 순서 요약

1. 저장소와 기존 PPT 규칙을 살펴봅니다.
2. 브랜드 자료와 예시 슬라이드를 모으고 출처를 기록합니다.
3. `presentation/design-system.md`에 색상·글꼴·레이아웃 기준을 씁니다.
4. 도구를 확인하고 2~3장짜리 PPTX 시제품을 만듭니다.
5. 편집 가능성, 한글 표시, 레이아웃을 확인합니다.
6. 자주 만드는 자료로 대표 PPT를 만듭니다.
7. 반복 절차를 `.agents/skills/pptx-maker/SKILL.md`에 저장합니다.
8. 직접 호출·일반 요청·자료 부족 등 시험 사례를 실행하고 지침을 다듬습니다.
