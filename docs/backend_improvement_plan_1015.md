**문서 식별자**: `docs/backend_improvement_plan_1015.md`  
**작성 일자**: 2026-10-15 (최종 업데이트: 2026-10-15)  
**관련 이슈 및 근거**: `error/1015-course1.png` (지정 공원 영역 이탈 및 코스 시간 불일치)  
**대상 시스템**: 백엔드 LangGraph ReAct 산책 경로 플래너 및 보행망 라우팅 엔진

## 1. 개요 및 배경

모바일 앱의 산책 설정 화면(`WalkSettingsView`)에서 **"지정 공원 둘레길"** 모드로 **[대전 송강근린공원, 목표 시간 40분]**을 선택하여 경로를 생성했을 때, 생성된 코스가 실제 지정 공원 부지를 크게 벗어나 남측 일반 도로 및 시가지(송강초등학교, 송강성당 등)까지 1.5km 이상 뻗어나가는 현상이 확인되었습니다. (`error/1015-course1.png`)

더 나아가, 현재 백엔드의 파일럿 공원 경로 생성 로직이 `pilot_park_routes.py`라는 **소수 파일럿 거점 하드코딩 데이터**에 의존하고 있어, **"현재 위치 기반(current_location)" 경로 생성 시 차도 노출 문제** 및 **"전국 임의의 신규 공원" 확장 시 공원 경계 이탈 문제**가 필연적으로 재발할 수밖에 없는 구조적 한계가 존재합니다.

본 문서는 특정 공원의 단순 좌표 결함 분석을 넘어, **전국 단위 임의의 위치 및 공원에서도 안전한 녹지 산책로를 동적으로 생성할 수 있는 근본적인 백엔드 일반화(Generalization) 아키텍처**를 수립합니다.

## 2. 발생 문제점 (Symptoms & Evidence)

```
[error/1015-course1.png 관찰 증거]
1. 설정 조건: 반려견 개3, 🌲 송강공원, 40분 산책, 폭신한 길/그늘이 많은 길
2. 생성 결과: "대전 송강근린공원 솔밭 숲길·잔디광장 완만루프" (3.2km · 약 60분)
3. 경로 이탈: 공원 북측 솔밭 산책로뿐만 아니라 남측의 송강그린아파트 남단, 송강초교,
            송강성당 주변 일반 도로(보도 및 이면도로)를 1.5km 이상 크게 우회함.
```

### 주요 문제점 요약
1. **공원 영역 이탈 (Park Boundary Violation)**:
   - 사용자는 "공원 둘레길"을 선택했으나, 실제 생성된 경로의 약 45% 이상이 공원 외부의 일반 시가지 도로에 위치함.
2. **목표 시간/거리 정합성 결여 (Duration/Distance Mismatch)**:
   - 사용자가 요청한 산책 시간은 **40분**(약 1.8~2.0km)이었으나, 반환된 경로는 **60분(3.2km)**으로 150% 이상 초과됨.
3. **가드레일 미작동 (Guardrail Failure)**:
   - 백엔드에 공원 경계 검사 함수(`is_route_inside_park_boundary`)가 존재함에도 불구하고 외부 이탈 코스가 정상 통과되어 프론트엔드로 전달됨.
4. **정적 데이터 종속으로 인한 전국 서비스 확장 불가**:
   - 대전/세종 4대 공원 외 다른 공원이나 현위치 기반 요청 시 안전한 녹지 추종 보장 불가.

## 3. 심층 근본 원인 분석 (Root Cause Analysis)

### 원인 ①: 백엔드 정적 OSM 좌표열(`SONGGANG_PARK_OSM_COORDS`) 자체의 오류
- **위치**: `backend/agent/pilot_park_routes.py` (라인 14)
- **분석**:
  - 송강근린공원의 실제 면적은 위도 `36.4312 ~ 36.4343`, 경도 `127.3805 ~ 127.3845` 범위의 공원 부지입니다.
  - 그러나 현재 파일에 하드코딩된 `SONGGANG_PARK_OSM_COORDS` 좌표열을 지리 정보(GIS)로 역추적한 결과:
    - **공원 내부 구간**: `[127.3805, 36.4328]` ~ `[127.3845, 36.4330]` (솔밭길/잔디광장)
    - **남측 이탈 구간**: `[127.3806, 36.4312]` ➔ `[127.3818, 36.4300]` ➔ `[127.3805, 36.4292]` ➔ `[127.3792, 36.4299]`
  - 위도 `36.4292`는 공원 경계선에서 남쪽으로 **약 250m 이상 떨어진 송강초등학교와 송강성당 앞 도로**입니다.
  - 초기 데이터 파이프라인에서 공원 내부 순환로가 아닌 **"공원 + 인근 주택가 연결 루프"** 전체가 하나의 정적 파일럿 코스로 잘못 등록되었습니다.

### 원인 ②: 공원 경계 폴리곤(`park_polygons_pilot.json`)의 가상 원형 버퍼
- **위치**: `backend/fixtures/park_polygons_pilot.json` (라인 731)
- **분석**:
  - `is_route_inside_park_boundary(coords, "songgang")` 함수는 좌표열이 공원 폴리곤 내부에 포함되는지 검사합니다.
  - 하지만 `park_polygons_pilot.json`에 정의된 `songgang` 폴리곤은 실제 지적도 경계가 아니라 **중심점(`36.4315, 127.3805`) 기준 반경 약 500m 원형 가상 버퍼(최남단 위도 `36.4272`까지 확장)**로 생성되어 있었습니다.
  - 남측 시가지(`36.4292`)가 이 가상 원형 폴리곤 내부에 넉넉하게 포함되어, 가드레일이 이탈을 감지하지 못하고 정상 코스로 승인했습니다.

### 원인 ③: 정적 데이터 하드코딩 방식의 구조적 한계 (전국 확장성 결여)
- **위치**: `backend/agent/pilot_park_routes.py` (`PILOT_PARK_COORDS_MAP`), `backend/agent/loop_route_planner.py`
- **분석**:
  1. **신규 공원 지원 불가**: `sejong`, `yurim`, `songgang`, `doan` 4개 외의 다른 공원이 지정되면 정적 코스가 없어 OSRM 실시간 탐색으로 넘어갑니다.
  2. **OSRM의 공원 경계 인식 불가**: OSRM은 공원의 지적 경계를 알지 못하므로, 출발점 기준 원형 웨이포인트가 공원 밖 4차선 차도나 상가 이면도로에 찍혀 **공원을 벗어나는 경로가 무조건 발생**합니다.
  3. **현위치 기반(`current_location`)의 녹지 선호 부재**: 현위치 주변에 훌륭한 근린공원이 있어도, OSRM은 단순 최단 보행로를 질의하므로 위험한 대로변으로 경로가 생성될 가능성이 높습니다.
  4. **최악의 폴백 위험**: OSRM 타임아웃 또는 도로망 단절 시 `_plan_rectangle_fallback`(건물과 하천을 가로지르는 허공의 직사각형)으로 퇴행할 위험이 상존합니다.

### [Phase 1] 즉시 적용 핫픽스 (Hotfix - 파일럿 안정화)

#### 1. `SONGGANG_PARK_OSM_COORDS` 좌표열 정밀 교정
- 남측 시가지 이탈 구간(위도 `36.4292 ~ 36.4308`)을 완전히 삭제.
- 송강근린공원 부지 내부(위도 `36.4312 ~ 36.4343`, 경도 `127.3805 ~ 127.3845`)만을 완전히 순환하는 **1.2 ~ 1.4km (약 25 ~ 30분 소요)** 보행로 루프로 교체.
- **수정 대상 파일**: `backend/agent/pilot_park_routes.py`

#### 2. 실제 공원 지적 경계선 폴리곤 반영 및 가드레일 강화
- 반경 500m 원형 가상 버퍼를 제거하고, 실제 카카오맵/OSM 지적도 기반의 송강근린공원 경계 Polygon GeoJSON으로 교체.
- `is_route_inside_park_boundary` 함수의 완충 여백(`poly.buffer(0.0005)`)을 **약 15m(`0.00015`)** 수준으로 엄격하게 제한하여 공원 경계 밖 도로 진출을 즉각 감지·차단.
- **수정 대상 파일**: `backend/fixtures/park_polygons_pilot.json`, `backend/agent/pilot_park_routes.py`

---

### [Phase 2] 시간대별 적응형 고도화 (Adaptability)

#### 1. 공원 모드 시간대별 코스 세분화 (Short / Medium / Long)
- **코스 1 (Short, 20~30분 / 약 1.0~1.3km)**: 중앙 잔디광장 둘레길 1회 완만 순환
- **코스 2 (Medium, 40~50분 / 약 1.8~2.2km)**: 외곽 숲길 산책로 포함 8자형 내부 교차 순환
- **코스 3 (Long, 60분 이상 / 약 3.0km+)**: 둘레길 2회 순환 또는 인접 녹지 보행로 연계 코스 *(공원 외곽 도로 진출 시 UI에 '공원 연계 녹지길' 및 일반 도로 주의 안내를 명시)*

#### 2. OSM 도로 태그 기반 라우팅 필터링 (Overpass / OSRM)
- 공원 모드(`origin_mode: "park"`) 시 허용 도로 태그 제한:
  - **허용**: `highway=footway`, `highway=path`, `highway=pedestrian`, `leisure=park`
  - **배제**: `highway=residential`, `highway=tertiary`, `highway=service` (차도 및 상가 이면도로)

### [Phase 3] 전국 단위 일반화 엔진 (Generalization Engine)

하드코딩된 정적 좌표에 의존하지 않고, **전국 어떤 공원이나 현위치에서도 안전한 공원 산책로를 자동 합성**하는 아키텍처입니다:

#### 1. Overpass API 기반 실시간 공원 보행로 동적 서브그래프 구축
- 임의의 공원이나 사용자가 지정한 위치에 대해 OSM Overpass API를 실시간 호출:
  ```overpass
  [out:json][timeout:5];
  // 지정 공원 경계(Polygon) 내부의 보행자 전용로만 동적 쿼리
  (
    way["highway"~"footway|path|pedestrian"](poly:"경계_위경도_목록");
    way["leisure"="park"](poly:"경계_위경도_목록");
  );
  out body geom;
  ```
- 공원 경계 밖으로 나가는 간선(Edge)을 물리적으로 배제한 **공원 내부 전용 보행 그래프**를 인메모리(NetworkX)로 빌드하여 완벽한 폐쇄 순환 루프(Eulerian/Hamiltonian Cycle)를 생성.

#### 2. 국토교통부 전국 도시공원 오픈데이터 공간 DB(PostGIS) 연계
- 공공데이터포털 **[전국도시공원정보표준데이터]** 공간 폴리곤(Shapefile/GeoJSON)을 백엔드 DB에 구축.
- 사용자가 전국 어디에서 공원을 선택하거나 인근 공원을 검색하더라도, 실제 지적도 경계를 즉시 불러와 가드레일(`contains`)을 100% 자동 검증.

#### 3. 현위치 기반(`current_location`) '공원 유인(Park Attraction) 3단계 루프'
- 사용자의 현위치 주변 반경 800m 내에 도시공원이나 하천 산책로가 존재할 경우:
  - **1단계 (접근)**: 현위치 ➔ 최단 보행로를 통해 가장 가까운 공원 진입로(Entrance)로 이동
  - **2단계 (순환)**: 공원 내부 순환로를 목표 산책 시간의 70% 이상 채우며 안전하게 산책
  - **3단계 (복귀)**: 다시 현위치로 안전 귀환
- 도심 아스팔트 차도 노출 시간을 획기적으로 줄이고, 반려견 관절 및 안전을 보호하는 웰니스 경로를 자동 완성.

## 6. 요약 및 추진 로드맵

1. **Step 1 (당장 수행 - 핫픽스)**:
   - `backend/agent/pilot_park_routes.py`의 `SONGGANG_PARK_OSM_COORDS`를 실제 공원 내부 순환선으로 교정하고 `park_polygons_pilot.json` 경계 다각형을 현실화하여 **외부 도로 이탈 결함을 즉시 종결**.
2. **Step 2 (스프린트 후속 - 고도화)**:
   - 4대 파일럿 공원 전체에 대해 20분/40분/60분 시간대별 적응형 순환 루프 데이터셋을 확장 구축.
3. **Step 3 (차기 릴리즈 - 일반화 엔진)**:
   - Overpass API 및 전국 도시공원 공간 DB를 연동하여 전국 단위 무제한 공원/현위치 동적 생성 엔진으로 전환.
