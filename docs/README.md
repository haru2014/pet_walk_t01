# 편안하개 프로젝트 문서 안내

문서의 실행 방법·API·구현 현황을 확인할 때는 아래 자료를 우선 참고하세요. 기획서, 스프린트 보고서, 날짜가 붙은 감사 자료는 작성 시점의 요구사항·관찰 결과를 보존하는 기록입니다. 현재 동작을 설명하는 문서와 충돌하면 최신 코드 기준 자료를 확인하고, 과거 내용을 지우지 말고 취소선과 기준일로 구분합니다.

| 목적 | 문서 |

| API 상세 요청·응답 예시와 코드 기준 라우트 보완 | [API 정의 및 구현 현황](07_편안하개_API_list.md) |
| 로컬 실행, 배포 절차와 날짜가 붙은 운영 기록 | [백엔드 실행·배포 가이드](09_백엔드_서버_실행_배포_가이드.md) |
| 단일 파일 및 영역별 설치·실행 도움말 | [Backend](../backend/README.md), [Frontend](../frontend/README.md) |

## 기획·요구사항 및 역사 기록

| 문서 묶음 | 경로 | 기준 |
|---|---|---|
| 문제 정의·팀 구성·스토리·프로젝트 제안·수행 일정 | `00_`–`06_` 문서 | 기획 및 요구사항 기준. 완료 상태는 현재 상태 보고서에서 별도 확인 |
| 구현·감사·실증 보고서 | `reports/` | 각 파일에 적힌 보고일 기준의 기록 |
| 담당자별 계획 | `implementation_plan/` | 계획 문서. 실제 반영 여부는 저장소 코드 기준으로 확인 |
| 외부 인프라와 운영 매뉴얼 | `guideline/` | 수동 계정·서비스 설정 절차. 운영 계정의 현재 값이나 상태를 보장하지 않음 |
| 화면·GIS·DB 참고 자료 | `reference/`, `screenshots/`, `mockup/`, `UI_design/` | 참고·설계 산출물. 배포 앱과 동일한 최신 화면임을 의미하지 않음 |

## 갱신 원칙

- 파일에 적힌 작성일·테스트 수·운영 주소는 원래 기록으로 보존하고, 현재 값과 다르면 기준일과 함께 취소선으로 표시합니다.
- 코드 정적 검토만 수행한 경우 테스트 통과, 실기기 동작, 외부 API 연결, 운영 배포를 확인했다고 쓰지 않습니다.
- 소스 코드와 설정 파일에서 직접 확인한 동작은 코드 경로를 함께 기록하고, 외부 계정 상태는 별도 검증 대상으로 남깁니다.
