## 🎙️ 2. 슬라이드별 발표 대본 (Script)

### Slide 01. 표지 (편안하개: 시작부터 완성까지의 개발 여정)
> "안녕하십니까, AI Native 반려견 맞춤형 안심 노면 산책 플랫폼 **'편안하개'**의 성과 발표를 맡은 팀 편안하개입니다.  
> 저희 프로젝트의 공식 문서들은 모두 `docs` 폴더에 체계적으로 기록되어 있고, 그 문서를 실제로 구현하며 치열하게 고민하고 부딪힌 여정은 `GitHub`의 717개 커밋과 210개의 PR, 75개의 이슈 속에 온전히 녹아 있습니다.  
> 오늘 발표에서는 기획 문서에서 출발하여 GitHub을 거쳐 실제 동작하는 완성도 높은 앱 서비스로 탄생하기까지의 전 과정을 투명하고 생생하게 소개해 드리겠습니다."

### Slide 02. [시작 1/3] 문제 정의와 기획의 출발 (Docs)
> "모든 프로젝트의 시작은 '풀고자 하는 문제가 무엇인가'라는 질문에서 시작됩니다. 저희는 `docs/04` AI 문제 정의서와 `docs/06` 제안서를 통해 반려견 보호자들이 매일 겪는 세 가지 고통을 정의했습니다.  
> 첫째, 반려견 관절을 위협하는 계단과 15도 급경사, 여름철 아스팔트 지면열을 사전에 알 수 없다는 점입니다.  
> 둘째, 길을 찾느라 스마트폰 화면에 시선이 뺏겨 자전거나 다른 맹견과의 돌발 충돌에 무방비해진다는 점입니다.  
> 셋째, 노령견이나 슬개골 취약견처럼 반려견마다 체급과 건강 조건이 다른데도 기존 지도 앱은 사람 중심의 최단거리만 추천한다는 점입니다.  
> 저희는 '계단을 피하고, 화면을 보지 않고 음성으로 걸으며, 내 반려견에 맞춘 안심길을 걷는다'는 가설을 세우고 개발에 착수했습니다."

### Slide 03. [시작 2/3] 5인 팀 빌딩과 R&R 아키텍처 (Docs)
> "명확한 문제를 풀기 위해 다섯 명의 엔지니어가 전문 영역을 나누었습니다. `docs/02` 팀 빌딩 문서에 정의된 R&R입니다.  
> 조현정 PM은 요구사항 관리와 LangGraph ReAct 에이전트 오케스트레이션을 총괄했습니다.  
> 전황진 님은 OpenStreetMap 보행망 태깅과 국토정보플랫폼 DEM 경사도, 기상청 지면온도 수지식을 맡았습니다.  
> 노희선 님은 FastAPI 기반 백엔드, 라우팅 어댑터, 1.5초 SLA 캐시 레이어를 구축했습니다.  
> 김승현 님은 React Native/Expo 기반 모바일 앱, 백그라운드 GPS 및 음성 안내 엔진, 빌드/배포를 담당했습니다.  
> 김정님 님은 긍정적 웰니스 UI 컴포넌트, 513개 프론트엔드 전수 검증, 그리고 5인 실사용자 CBT 설계를 주도했습니다.  
> 저희의 협업은 개별 모듈에 갇히지 않고, 엄격한 API 스키마와 통합 시나리오를 통해 하나로 연결되었습니다."

### Slide 04. [시작 3/3] 애자일 요구사항과 DoD 수립 (Docs)
> "기획을 실제 소프트웨어로 구현하기 위해 `docs/03` 애자일 사용자 스토리 정의서를 작성했습니다.  
> 총 7개 에픽, 15개 핵심 MVP 스토리로 62 Story Points를 도출했습니다.  
> 자연어 질의 의도 추출과 로컬 프로필 백업을 다루는 Epic A, 계단과 15도 급경사를 차단하고 지면열을 감안하는 Epic B, 3색 지도 렌더링과 73dB 짖음 감지 음소거의 Epic C, 그리고 Local-First 기록과 200m 마스킹을 다루는 Epic E부터 G까지 체계적인 인수 조건을 수립했습니다.  
> 특히 '단위 테스트 100% 통과, 정적 타입 검사 무결성, 실기기 동작 확인'이라는 엄격한 완료 정의(DoD)를 통과해야만 개발 완료로 판정했습니다."

### Slide 07. [여정 3/4] GitHub 이슈로 본 4대 핵심 난제 극복기 (GitHub)
> "실제 제품을 만드는 과정은 예상치 못한 난제와의 싸움이었습니다. GitHub Issue로 투명하게 관리한 대표적 4가지 극복 사례입니다.  
> 첫째, Issue #22 도심 빌딩 관통 버그입니다. 초기 라우팅이 단순 직선 보간으로 아파트 단지와 빌딩을 뚫고 지나가는 문제가 있었습니다. 이를 해결하기 위해 OSRM 실제 보행 도로망 기반 정밀 라우팅 엔진으로 전면 교체했습니다.  
> 둘째, Issue #28 응답 지연 병목입니다. 10개 지점 순차 계산으로 4.8초가 걸리던 것을 OSRM 병렬 호출과 10분 인메모리 반경 캐싱을 적용해 Warm P95 112.55ms로 40배 이상 단축했습니다.  
> 셋째, Issue #221/222 다크 포켓 모드 오류입니다. 주머니 속 시선 해방 모드를 해제할 때 화면이 튕기는 현상을 네비게이션 상태 머신 재설계로 바로잡았습니다.  
> 넷째, Issue #227 맹견 출몰 제보입니다. 공원 내 들개 출몰 시 일반 공사 구역으로 처리되던 문제를 바로잡아 'dog_danger' 위험 타입을 신설하고 라우팅 시 해당 구역을 자동 우회하도록 개선했습니다."

### Slide 08. [여정 4/4] 엄격한 PR 코드 리뷰와 TDD 문화 (GitHub)
> "어떻게 210개의 PR을 단 하나의 치명적 배포 사고 없이 메인에 머지할 수 있었을까요?  
> 첫째, 5인 멤버가 각각 `feat/memberX` 기능 브랜치에서 TDD 방식으로 테스트 코드를 먼저 작성했습니다.  
> 둘째, PR이 생성되는 즉시 GitHub Actions CI가 가동되어 Vitest와 Pytest, 그리고 `tsc --noEmit` 정적 타입 검사를 실행했습니다.  
> 셋째, 인터페이스 규격과 예외 처리를 상호 코드 리뷰로 확인하고, 승인된 코드만 `main`에 안전하게 병합했습니다.  
> 이 자동화 루프 덕분에 요구사항(docs/03)부터 이슈, PR, 커밋까지 1:1로 완벽한 추적성을 유지할 수 있었습니다."

### Slide 09. [완성 1/3] 완성된 시스템 아키텍처 (Docs & Code)
> "이 치열한 여정의 결과로 완성된 시스템 아키텍처를 소개합니다. `docs/10` 아키텍처 설계서에 4+1 View로 명세화된 구조입니다.  
> 핵심은 **'Local-First 프라이버시와 지능형 에이전트의 조화'**입니다.  
> 자택 좌표, 반려견 프로필, 실시간 GPS 이동 궤적은 일체 서버로 전송하지 않고 사용자 모바일 기기 내부 `AsyncStorage`에만 보관합니다.  
> 백엔드 서버는 무상태(Stateless) API로 동작하며, LangGraph ReAct 플래닝 에이전트가 OSM 무장애 보행망, DEM 10m 경사도, 기상청 지면온도 데이터를 조합해 112ms 만에 최적의 경로를 반환합니다.  
> 사용자가 코스를 커뮤니티에 공유할 때만 출발지 반경 200m를 자동으로 잘라내는 공간 마스킹이 동작합니다."
