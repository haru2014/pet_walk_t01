# 지면온도 추정 오차 평가: 기상청 관측 지면온도 대비 (US-F1·US-B2, P1)

> 작성: 전황진 (데이터·GIS) · 기준: main `7a61c0b`에서 평가(이후 #118은 참고 문서만 추가, 추정식 변경 없음) · 작성일 2026-10-18
> 목적: 서버의 지면온도 추정식(`backend/services/weather_context.py`)이 실제 지면온도와 얼마나 맞는지 확인한다. 현장 측정 장비가 없어, 기상청 종관기상관측(ASOS) 시간자료의 관측 지면온도를 기준으로 삼았다.

## 1. 방법

| 항목 | 내용 |
|---|---|
| 관측 자료 | 공공데이터포털 "기상청_지상(종관, ASOS) 시간자료 조회서비스". 대전(133)·세종(239), 2026-06-01 ~ 2026-10-17, 6,671시간 |
| 비교 값 | 관측 지면온도 `ts` |
| 추정 값 | 서버 식 `지면온도 = 기온 + 일사 가중치 × 상승폭`. 기온은 관측 `ta`, 일사 가중치는 관측 일사 `icsr`(MJ/m²)를 W/m²로 바꿔 1000으로 나눈 값(서버의 Open-Meteo 일사 처리와 같음) |
| 상승폭 | 기본 15℃(위험도·골든타임 판정에 쓰는 값), 노면별 아스팔트 18 / 보도블록 14 / 탄성 12 / 자갈 10 / 흙 8 / 잔디 4 |

- 관측 기온과 관측 일사를 넣었으므로, 이 평가는 **추정식 자체의 오차**다. 운영에서는 예보 기온·예보 일사를 쓰므로 예보 오차가 더해진다(이번 평가에 포함하지 않음).
- 관측소 지면온도는 관측소 노지(맨땅)에서 잰 값으로 알고 있다. 재질은 기상청 관측 지침으로 다시 확인해야 한다. 아스팔트·보도블록 관측값은 없다.

## 2. 결과

### 2.1 오차 (추정 − 관측, ℃)

| 구간 | 기본(15) 평균 / 절대평균 | 흙(8) 평균 / 절대평균 | 잔디(4) 평균 / 절대평균 |
|---|---|---|---|
| 전체 6,671시간 | −0.3 / 2.1 | −1.9 / 2.2 | −2.7 / 2.9 |
| 낮(일사 있음) 3,845시간 | **+0.6 / 2.5** | −2.1 / 2.6 | −3.6 / 3.8 |
| 한낮 11~15시, 6~8월 920시간 | +1.3 / 3.0 | −3.2 / 3.5 | −5.8 / 5.8 |
| 관측 지면 35℃ 초과 1,079시간 | +0.3 / 3.2 | **−4.5 / 4.7** | −7.3 / 7.3 |

- **기본 추정(상승폭 15℃)은 관측 맨땅 지면온도와 잘 맞는다.** 낮 평균 +0.6℃, 절대평균 2.5℃다.
- 맨땅 관측에 가장 잘 맞는 상승폭은 **12.6℃**다(낮 시간 최소제곱 적합). 해가 없을 때는 관측 지면이 기온보다 평균 1.6℃ 높다(추정식은 0으로 가정).
- 시간대별 평균 편향(기본 추정)은 9~12시 +1.6~+2.1℃(높게 추정), 14~17시 +0.5~+0.7℃, 19시 −1.0℃(낮게 추정)다.
- 가장 뜨거웠던 관측은 세종 2026-08-08 14시다. 기온 36.6℃, 지면 56.4℃였다.

### 2.2 위험도 판정 비교 (기본 추정 기준, 관측 → 추정)

| 관측 \ 추정 | 안전 | 주의 | 위험 |
|---|---|---|---|
| 안전 (≤35℃) 5,592 | 5,253 | 339 | 0 |
| 주의 (35~45℃) 937 | **93** | 787 | 57 |
| 위험 (>45℃) 142 | **0** | 79 | 63 |

- 관측이 "위험"인 142시간 중 **"안전"으로 판정한 시간은 없다.** 다만 79시간은 한 단계 낮은 "주의"로 판정했다.
- 관측이 주의 이상인 1,079시간 중 93시간(8.6%)을 "안전"으로 판정했다. 10~17시에 고르게 퍼져 있고 세종에 많다(세종 67, 대전 26). 이때 관측이 추정보다 평균 3.6℃(최대 10.8℃) 높았다.
- 반대로 관측 "안전" 339시간을 "주의"로 판정했다(과대 경고).

## 3. 발견 사항

### 중 1. 흙길 추정이 관측 맨땅보다 낮다
- 흙(상승폭 8℃) 추정은 관측 맨땅보다 한낮에 3.2℃, 관측 35℃ 초과 시 4.5℃ 낮다. 맨땅 관측에 맞는 상승폭은 12.6℃다.
- 앱은 흙길을 "시원한 노면"으로 권하므로, 실제보다 시원하게 안내할 수 있다.
- 조치 제안: 관측소 지면 재질을 확인한 뒤, 흙 상승폭을 12~13℃ 근처로 조정할지 검토한다. 잔디(4℃)는 맨땅과 재질이 달라 이 자료로 직접 판단하지 않는다.
- **반영 (후속 PR)**: 기상청 지상기상관측지침(2024.10) 12.2절이 "온도계의 주위 30cm 정도는 잔디를 제거하여 맨땅이 노출되도록 한다… 감지부가 노출되지 않도록 금속부분을 흙으로 얇게 덮어"라고 정한다. 따라서 관측값은 맨땅 표면 바로 아래 온도다. 흙 상승폭을 12.6℃로 바꿨다(서버 `SURFACE_HEAT_GAIN_MAP`, 대체 응답, 앱 오프라인 계산). 햇볕을 직접 받는 흙길 표면은 이보다 조금 더 뜨거울 수 있다.

### 중 2. 주의 이상인 시간의 8.6%를 "안전"으로 판정한다
- 위험(>45℃)을 안전으로 판정한 적은 없지만, 35~45℃ 구간 일부를 안전으로 본다.
- 조치 제안: 안전 기준(35℃)에 여유를 두거나(예: 추정 33℃ 초과부터 주의), 해가 없을 때의 +1.6℃ 차이를 식에 반영하는 방안을 검토한다. 위험도 기준은 AI 점수·안내 문구와 맞물려 있어 팀과 함께 정한다.

### 한계
- 아스팔트·보도블록·탄성포장은 관측값이 없어 검증하지 못했다. 맑은 날 적외선 온도계로 현장 보조 측정이 필요하다.
- 관측소는 공원이 아니며, 그늘·주변 건물 영향이 다르다.
- 운영의 예보 오차(기상청 예보 기온, Open-Meteo 예보 일사)는 포함하지 않았다.

## 부록. 재현
- 스크립트는 로컬 확인용이라 저장소에 넣지 않았다. ASOS API 키는 `backend/.env`의 `ASOS_SERVICE_KEY`(git 제외)를 썼다.
- 요청: `getWthrDataList`, `dataCd=ASOS`, `dateCd=HR`, `stnIds=133|239`, 월별 `numOfRows=999`.
- 사용 필드: `tm`, `ta`(기온), `ts`(지면온도), `icsr`(일사, MJ/m²). `ta`나 `ts`가 비어 있는 시간은 뺐다.
